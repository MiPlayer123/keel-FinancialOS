# Navigation, sidebar & global layout

## Convergent patterns
(what ≥3 competitors ALL do in this dimension that KEEL does not — the strongest signals)

1. **Accounts live in the persistent nav rail as balance-bearing, click-into rows grouped by type with a group subtotal.** Copilot (`copilot-mac-01` — "MY ACCOUNTS" section, collapsible type groups "Credit cards / Depository / Investment", each row = colored dot + name + right-aligned balance), YNAB (`ynab-web-01` — CASH/CREDIT/LOANS/TRACKING/CLOSED headers each with a signed rollup total, each account a clickable row with its own balance), Quicken (`quicken-classic-community-01` — persistent ACCOUNTS sidebar grouped Banking/Savings/Credit Card/Investing/Property & Debt, every group a rolled-up subtotal), Simplifi (`quicken-simplifi-community-01` — nested account tree with a balance right-aligned at *every* nesting depth), Monarch (`monarch-community-01` / `monarch-web-01` — accounts panel grouped with subtotals + total). KEEL shows account *names* only, no balances, no subtotals (`keel-core-01`, `accounts-desktop.png`).

2. **Search / jump-to reachable from every screen** (global search field or ⌘K command palette). Copilot (`copilot-mac-01`, `copilot-web-01` — a search field pinned at the very top of the sidebar on every screen), Ramp (`ramp-community-01` — top-bar "Search or jump to…" + "⌘K Search for anything"), Brex (`brex-community-01` — top-bar "Search or jump to…" with a `⌘K` hint), Quicken (`quicken-classic-community-01` — global "Search a payment or deposit" box in the top chrome). KEEL has search *only* inside the Ledger toolbar; nowhere else (`keel-core-01`, `keel-mobile-04`).

3. **A persistent top bar carrying global utilities** (notifications bell, help, settings/theme, avatar). Simplifi (`quicken-simplifi-community-01` — bell + "?" + gear + avatar cluster top-right of every screen), Ramp/Brex (`brex-community-01` — search, bell, help/book, sun theme-toggle, Support, user menu), Monarch (`monarch-iphone-01` — persistent bell), Rocket Money (`rocket-money-community-01` — bell + gear before the page title), Quicken (`quicken-classic-community-01` — notification bell w/ badge, calendar, calculator). KEEL desktop has **no top bar at all**; the theme toggle, avatar and sign-out are crammed into the sidebar footer (`accounts-desktop.png`).

4. **A persistent mobile navigation surface (bottom tab bar or an always-visible tab strip).** YNAB (`ynab-web-01` — 5-item bottom nav Home/Plan/Spending/Accounts/Reflect with a badge), Rocket Money (`rocket-money-community-01` — bottom tab bar Dashboard/Recurring/Spending/Transactions/More), Copilot (`copilot-iphone-01` — persistent horizontally-scrollable 8-tab strip under the header). KEEL mobile is a hamburger drawer only — a single ☰ top-left and nothing else (`keel-mobile-04`, `dashboard-mobile-390.png`).

5. **Net worth (and group subtotals) surfaced inside the accounts rail itself**, always one glance away regardless of the active page. Quicken (`quicken-classic-community-01` — "Net Worth" + "Credit Score" pinned at the bottom of the accounts sidebar on every screen), Simplifi (`quicken-simplifi-community-01` — "Net Worth / All Accounts" total pinned atop the accounts panel), YNAB (`ynab-web-01` — per-group signed rollups), Copilot/Monarch (group subtotals). KEEL's sidebar tree carries no totals of any kind; net worth appears only on the Home and Accounts *pages* (`keel-core-01`).

## Findings

### NAVLAYOUT-1 — Sidebar account tree shows names but no balances, no subtotals, and no clear click-into-account affordance [P1]
- **Evidence:** `design/current/2026-07-16/accounts-desktop.png`; `keel-core-01` §Information architecture ("rendered on every page… as static sub-items", "no visible expand/collapse chevron"); `keel-ops-03` (same). Competitors: `copilot-mac-01`, `ynab-web-01`, `quicken-classic-community-01`, `quicken-simplifi-community-01`, `monarch-community-01`.
- **Competitors:** Every account-centric competitor puts the accounts list in the persistent rail as *balance-bearing, clickable* rows grouped by type with a group subtotal: Copilot (dot + name + right-aligned balance, tap → account detail), YNAB (per-account balance + reconciled checkmark, group header rollup), Quicken (type groups each with a rolled-up subtotal, Net Worth pinned at bottom), Simplifi (balance at every nesting depth). This is exactly the "accounts-with-balances tree, clickable straight into accounts" pattern the founder called out.
- **KEEL today:** The sidebar renders "ASSETS → CHASE COLLEGE, Personal Profile / LIABILITIES → CREDIT CARD" as bare text sub-items with **no balance next to any name, no Assets/Liabilities subtotal, and no net-worth total** — the one job a persistent accounts rail exists to do (tell you where you stand at a glance) is unfulfilled. The census can't even confirm the rows navigate anywhere (`keel-core-01`: "static sub-items"); the actual clickable, balance-bearing rows live only on the full Accounts *page*.
- **Fix:** Turn the sidebar account tree into the Copilot/Quicken pattern: each account row = name + right-aligned balance (mono `tabular-nums`, red only for negative), each ASSETS/LIABILITIES header carries its subtotal, and a "Net worth $14,763.85" line pins under the group; each row links directly to that account's register (already exists per `W1.9`). Keep it 390px-safe by collapsing to balances-only in the drawer.
- **Maps to:** NEW (extends DESIGN-NOTES "accounts grouped by type with a group subtotal, tap → detail"; the *page* is built, the *rail* is not).

### NAVLAYOUT-2 — No global search / command palette; search is trapped inside the Ledger [P1]
- **Evidence:** `keel-core-01` §Controls (search input exists only on Ledger), `keel-mobile-04` (Ledger-only search), `accounts-desktop.png` (no search anywhere in chrome). Competitors: `ramp-community-01`, `brex-community-01`, `copilot-mac-01`, `quicken-classic-community-01`.
- **Competitors:** Ramp and Brex both ship a top-bar "Search or jump to…" with a `⌘K` shortcut hint — a command palette that jumps to any transaction, account, page, or action. Copilot pins a search field at the top of the sidebar on every screen. Quicken keeps a global "Search a payment or deposit" box in the top chrome. Search-from-anywhere is table stakes.
- **KEEL today:** Search exists as a single "Search transactions" input *inside* the Ledger toolbar only. To find an account, a payee, or jump to a page from Reports/Budgets/Settings you must first navigate to the Ledger. There is no ⌘K, no global search, no jump-to. FEATURE-GAP-REPORT lists Search as "Missing" (#25) at the capability level; this finding adds the specific chrome/interaction gap.
- **Fix:** Add a global search entry point in a new top bar (see NAVLAYOUT-4) bound to ⌘K, indexing transactions + accounts + nav destinations + primary actions (Add transaction, Record transfer, New rule). Wave-1 can ship a nav-destination + account jumper on the client immediately; wire transaction results to `keel_search_transactions` when it lands.
- **Maps to:** NEW (relates to FEATURE-GAP #25 "Search: Missing" and #3 transactions-search proc, but the from-anywhere command-palette surface is not in PLAN).

### NAVLAYOUT-3 — Mobile has no persistent nav; every section switch costs a drawer open [P1]
- **Evidence:** `keel-mobile-04` §Information architecture ("top bar with a hamburger icon (☰)… The hamburger is never opened"), `dashboard-mobile-390.png` (☰ top-left, centered wordmark, nothing else). Competitors: `ynab-web-01`, `rocket-money-community-01`, `copilot-iphone-01`.
- **Competitors:** YNAB (5-item bottom bar Home/Plan/Spending/Accounts/Reflect), Rocket Money (bottom bar Dashboard/Recurring/Spending/Transactions/More), and Copilot (persistent horizontally-scrollable tab strip) all keep primary navigation one tap away on phone. Only Monarch uses a drawer — and it's the outlier.
- **KEEL today:** The entire 13-item nav lives behind a hamburger that is never persistent. On a 390px screen, moving from Home to Ledger to Budgets is drawer-open → scan 13 items → tap, *every time* — the highest-frequency interaction on the highest-frequency device is the slowest. CLAUDE.md Law 8 mandates 390px usability; a drawer-only IA meets the letter but not the daily-driver spirit.
- **Fix:** Add a bottom tab bar for the 4–5 most-used destinations (Home, Ledger, Accounts, Review, +More) with the Review badge (NAVLAYOUT-9). Keep the drawer for the long tail (Statements, Reimbursements, Paychecks, Connections, Settings). ≥44px targets per DESIGN-NOTES.
- **Maps to:** NEW.

### NAVLAYOUT-4 — Desktop has no top bar; global utilities are missing or crammed into the sidebar footer [P1]
- **Evidence:** `accounts-desktop.png` (utilities are footer-jammed: email, sun icon, "N" avatar, Sign out), `keel-ops-03` §IA (login has a top bar with logo + theme toggle, but the authed app does not). Competitors: `quicken-simplifi-community-01`, `brex-community-01`, `rocket-money-community-01`, `monarch-iphone-01`, `quicken-classic-community-01`.
- **Competitors:** A persistent top bar is universal — Simplifi (bell + "?" + gear + avatar on every screen), Ramp/Brex (search, bell, help, theme toggle, Support, user menu), Rocket (bell + gear preceding the title), Monarch/Quicken (notification bell, some with badge). It's where global search, sync status, notifications, help, and the account menu live.
- **KEEL today:** There is no top bar in the authed app. Notifications don't exist (FEATURE-GAP #26 Missing), help doesn't exist, global sync status only appears on the Home "Accounts" card ("Updated 21m ago ↻ Sync", `dashboard-desktop.png`), and the account menu/theme toggle are wedged into the sidebar footer where the avatar collides with "Sign out" (NAVLAYOUT-5). The chrome has nowhere to put the growing set of global affordances (search, notifications, entity switcher, sync).
- **Fix:** Introduce a slim persistent top bar: left = page title / breadcrumb, center-or-left = ⌘K global search, right = sync status + notifications bell + help + avatar menu (moving theme toggle + Sign out out of the footer). This is also the natural home for a future entity switcher (FEATURE-GAP #3/#13, multi-entity thesis).
- **Maps to:** NEW.

### NAVLAYOUT-5 — Sidebar footer avatar overlaps "Sign out"; app reads as broken/unfinished [P2]
- **Evidence:** `accounts-desktop.png` (the black "N" circle sits directly on top of the "Sign out" label — renders as "S​gn out"), `keel-money-02` §IA and `keel-ops-03` §IA both flag it verbatim ("avatar circle sits directly on top of the sign-out label"). Present on *every* authed screen.
- **Competitors:** Every competitor's account/user affordance is cleanly laid out — YNAB's plan switcher block, Simplifi's avatar-in-top-bar, Ramp/Brex's "Olivia Wilson ⌄" menu. None overlap.
- **KEEL today:** A z-index/layout collision in the sidebar footer makes the primary sign-out control partially unreadable and the whole footer look unfinished — a trust-corroding first impression on a finance product where polish signals reliability. The same floating "N" even appears bottom-left on the pre-auth login screen where no session UI belongs (`keel-ops-03` open question).
- **Fix:** Move the account menu (avatar + email + Sign out + theme) into the new top-bar avatar menu (NAVLAYOUT-4), or, if kept in the footer, lay it out as a single row (avatar · name · chevron) with Sign out inside the opened menu. Remove the avatar from the unauthenticated login shell.
- **Maps to:** NEW.

### NAVLAYOUT-6 — Mobile floating "N" button sits on top of content, obscuring a money figure [P2]
- **Evidence:** `dashboard-mobile-390.png` (black "N" circle overlaps the "Biggest purchase · 7 days / $895.33" card), `keel-mobile-04` §IA ("floating circular button… on Dashboard it visually sits on top of/near the 'Biggest purchase' card"; purpose unlabeled).
- **Competitors:** Copilot/Monarch/YNAB floating actions (e.g. YNAB's "+ Transaction" pill) are anchored clear of content, bottom-right, and clearly labeled; none occlude a number.
- **KEEL today:** An unlabeled fixed launcher overlaps card content — and on a money app, overlapping a dollar figure is worse than overlapping chrome. Its function is undiscoverable (no label/tooltip) and it competes with the future bottom tab bar (NAVLAYOUT-3) for the same screen edge.
- **Fix:** Give it a label/purpose or fold it into the bottom bar; at minimum reposition so it never overlaps a card, and add bottom padding so scrolled content clears it. Reconcile with the bottom-tab-bar decision so there's one mobile action system, not two.
- **Maps to:** NEW.

### NAVLAYOUT-7 — Net worth and account subtotals never appear in the nav/rail; they're re-derived per page [P2]
- **Evidence:** `keel-core-01` §IA (Home's net position and its bottom Accounts list "duplicate the Accounts page's net worth and per-account balances verbatim"); `accounts-desktop.png`, `dashboard-desktop.png`. Competitors: `quicken-classic-community-01`, `quicken-simplifi-community-01`, `monarch-iphone-01`.
- **Competitors:** Quicken pins "Net Worth" (+ Credit Score) at the bottom of the always-present accounts sidebar; Simplifi pins "Net Worth / All Accounts" atop its accounts panel; Monarch/Copilot show group subtotals in the rail. The anchor number is available on every screen without navigating.
- **KEEL today:** Net worth ($14,763.85) is computed and shown on Home *and* re-shown on Accounts, but it is absent from the persistent chrome — from Ledger, Reports, Budgets, or Settings you cannot see your net position without leaving the page. The sidebar tree, which is the obvious home for it, carries no totals at all.
- **Fix:** Fold this into NAVLAYOUT-1: subtotals on the ASSETS/LIABILITIES headers and a "Net worth" total at the foot of the sidebar account group (backend already computes it via `keel_net_worth_as_of`, FEATURE-GAP #14). DESIGN-NOTES already calls net worth "the anchor."
- **Maps to:** NEW (compute exists; surfacing in rail is new).

### NAVLAYOUT-8 — 13-item flat nav with no grouping or dividers strains scanning [P2]
- **Evidence:** `keel-core-01` §IA (full 13-item order, "grouped together… but are not visually grouped (no section header/divider)"), `keel-money-02` §IA (same), `accounts-desktop.png`. Competitors: `ramp-community-01`, `copilot-mac-01`.
- **Competitors:** Ramp separates nav clusters with dividers (primary items · Accounting group · My Ramp · Settings pinned at the very bottom). Copilot keeps its primary list to 7 and pushes accounts into a separate labeled "MY ACCOUNTS" section. Most competitors run 7–10 top-level items, visually chunked.
- **KEEL today:** Thirteen peer items in one undifferentiated column (Home, Accounts, Ledger, Recurring, Budgets, Goals, Reports, Paychecks, Reimbursements, Statements, Review, Connections, Settings). The census notes a latent grouping (money-shaping vs. ops/admin) that the UI never expresses. Settings and Connections aren't pinned apart from daily surfaces; the eye must scan all 13 to find anything.
- **Fix:** Add lightweight section labels/dividers — e.g. a "Manage" group (Ledger, Recurring, Budgets, Goals, Paychecks, Reimbursements), a "Reports" pin, and an "Admin" cluster (Statements, Connections, Settings) pinned to the bottom, with Review carrying its badge (NAVLAYOUT-9). Don't add depth — just chunk the flat list.
- **Maps to:** NEW.

### NAVLAYOUT-9 — Nav carries no badges/counts; the Review queue gives no ambient signal [P2]
- **Evidence:** `keel-core-01` / `keel-mobile-04` (no badges anywhere; Review is captured empty), `accounts-desktop.png`. Competitors: `copilot-mac-01` (Transactions nav badge "3"/"6" = to-review count), `ramp-community-01` (Inbox 44, Insights 8, Reimbursements 6 counts), `ynab-web-01` (Home badge "2").
- **Competitors:** Copilot badges the Transactions nav item with the review-queue count; Ramp badges nearly every nav item with its pending count; YNAB badges Home with new-transaction count. The count is the ambient nudge that pulls the user into the suggest→approve loop.
- **KEEL today:** The Review page is the heart of KEEL's suggest→approve thesis (Law 2), yet the nav gives zero signal that anything is waiting — the user must click Review to discover it's empty or full. No count on Review, Recurring (detected-but-unconfirmed), or anywhere.
- **Fix:** Ship the planned Review badge = suggested-transfers + recurring-suggestion count on the Review nav item (and mirror on the mobile bottom bar / drawer). Consider a Recurring "N detected" badge too.
- **Maps to:** **W1.5** (Review badge = suggested transfers + recurring count) — already planned; this finding confirms the convergent signal and asks to extend to mobile.

### NAVLAYOUT-10 — Full-page account detail wastes the horizontal space competitors use for master-detail [P2]
- **Evidence:** `accounts-desktop.png` (Accounts page is mostly whitespace below 3 rows — `keel-core-01`: "the page is mostly white space"; account rows carry a ">" chevron implying a *separate* full-page detail). Competitors: `copilot-mac-01`, `quicken-simplifi-community-01`, `quicken-classic-community-01`.
- **Competitors:** Copilot uses a two-pane master-detail everywhere (accounts/investments/recurrings/transactions list on the left, selected-item detail with chart + register on the right). Simplifi keeps the accounts tree panel *beside* the content so you never lose account context. Quicken keeps the accounts sidebar + register side-by-side. The wide desktop viewport does two jobs at once.
- **KEEL today:** Desktop layout is a single content column against a ~330px sidebar, leaving large empty regions (the census repeatedly flags whitespace on Accounts, Reimbursements, Statements). Drilling into an account appears to fully replace the page (chevron → separate route), so you lose the accounts list and must back out to switch accounts.
- **Fix:** Once the sidebar tree becomes clickable+balance-bearing (NAVLAYOUT-1), clicking an account can load its register in the main pane while the rail keeps all accounts + balances visible — a lightweight master-detail without a second panel. For account detail specifically, keep the accounts list visible (rail highlight = current account).
- **Maps to:** NEW (account-detail register is `W1.9`; the retained-context layout is new).

### NAVLAYOUT-11 — Theme toggle is a bare, unlabeled icon buried in the footer [P3]
- **Evidence:** `accounts-desktop.png` (sun icon, no label, footer), `keel-ops-03` §Controls. Competitors: `brex-community-01` (sun theme toggle in the top-bar utility cluster), `copilot-iphone-01` ("Light mode, when you need it" — dark/light is a first-class, pixel-identical token swap).
- **Competitors:** Theming is present and prominent — Brex/Ramp put the sun toggle in the top bar next to help/notifications; Copilot markets the light/dark pair explicitly and confirms it's a clean token swap with no layout change.
- **KEEL today:** KEEL *has* a theme toggle (good), but it's an unlabeled sun icon in the crowded footer next to the colliding avatar (NAVLAYOUT-5), easy to miss and easy to mis-hit. No evidence of a system/auto option.
- **Fix:** Move the toggle into the top-bar utility cluster (NAVLAYOUT-4) or the avatar menu with a label ("Appearance: Light / Dark / System"). Verify dark mode is a complete token swap across all captured surfaces (Ledger's mono register, charts, red-for-negative).
- **Maps to:** NEW.

### NAVLAYOUT-12 — Login shell is inconsistent with the app and off-center [P3]
- **Evidence:** `login-desktop.png` via `keel-ops-03` §Layout ("form floating in the page, off-center to the right… large empty region to the left"), and the stray footer avatar appearing pre-auth.
- **Competitors:** Not directly evidenced (competitor sets are authed marketing), but the general bar is a centered, balanced auth card.
- **KEEL today:** The sign-in form floats right-of-center with a large empty left region, and a session-only "N" avatar leaks onto the pre-auth screen — small but it's the literal first screen a user sees.
- **Fix:** Center the auth card; remove any session/avatar chrome from the unauthenticated shell; keep only logo + theme toggle in the pre-auth top bar. (The visible local-dev credential box on the production-dated login is a secret-boundary concern for a different dimension, but flagged here for adjacency.)
