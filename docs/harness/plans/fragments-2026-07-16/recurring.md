# Recurring & subscriptions

Ground-truth note: KEEL's Recurring page (`design/current/2026-07-16/recurring-desktop.png`, census `keel-money-02.md` L40-45) is captured **entirely in its empty state** — an H1 "Recurring", a one-line banner ("Rent, insurance, a paycheck — anything you know is coming…"), a single "Bills & scheduled" section with a "+ Add" outline button, and a dashed empty panel "No recurring activity detected yet / Detection runs nightly." The backend is real (gap report `#6`: `recurring_series`, `recurring_occurrences`, `recurring_candidate_versions`, confirm/pause/resume/cancel/reject, evidence + confidence bps are Implemented) and `PLAN-FEATURE-PARITY.md` W1.1 describes an Active/Suggested/Paused + Upcoming-30d list. So most findings below are about **surface anatomy that is absent or unplanned**, judged against the populated views every competitor ships. No mobile recurring screenshot exists in the drop, so 390px behavior (Law 8) is unassessable and flagged where load-bearing.

## Convergent patterns
(what ≥3 competitors ALL do here that KEEL does not)

1. **A month-grid calendar of due dates** with items rendered in day cells. Monarch: full calendar, merchant chips stacked in each day cell, "Today" badge, month paging (`monarch-community-03.md` L46-55). Simplifi: calendar with dot-per-day markers, today outlined, prev/next + "Today" (`quicken-simplifi-community-02.md` L27, `-03.md` L58). Rocket Money: right-rail calendar widget, dot-under-date = "has scheduled item" (`rocket-money-community-01.md` L27,52). Copilot: per-series Jan–Dec dot timeline (`copilot-community-02.md` L32). **KEEL has no calendar view at all**, despite its own copy promising "projects it into your balance curve."

2. **A per-series detail drill-in** showing cadence, next amount/date, and matched-transaction history. Copilot master/detail pane with NEXT PAYMENT + monthly timeline + Key Metrics + per-series transaction list (`copilot-community-02.md` L17,29-32). Simplifi reminder-series modal with amount-history bar chart, "Coming Up", "History" list (`quicken-simplifi-community-03.md` L38-53). Monarch calendar-chip popover: cadence + last 3 matched charges + "View all 12 transactions" (`monarch-community-03.md` L13,82). **KEEL has no detail route** for a series.

3. **Per-occurrence status states** distinct from the series: confirmed/paid vs projected/upcoming vs overdue/missed. Monarch encodes confirmed-vs-projected per occurrence via green-checkmark-and-colored-chip vs plain chip (`monarch-community-03.md` L77,87,95). Copilot uses literal "Overdue" in the date column + checkmark (`copilot-community-02.md` L25,44,85). Simplifi shows a per-instance "Paid" label adjacent to the amount (`quicken-simplifi-community-02.md` L54). Quicken Classic taxonomy: Overdue (red) / Auto / Due (`quicken-classic-community-01.md` L42,66). **KEEL's empty state only says "shows it as due"** — no paid/missed/overdue/upcoming vocabulary is evidenced.

4. **An aggregate spend total** for the recurring set. Rocket Money: "You spend $5,474/yearly" header, and per-bucket "$4,113 per year" / "$4,095 per year" (`rocket-money-community-01.md` L25,32). Copilot: "$25 left to pay / $2,063 paid so far" progress ring + yearly Key Metrics (`copilot-community-02.md` L25,32). Simplifi: Summary card Income/Expenses/Net over the window (`quicken-simplifi-community-02.md` L27). **KEEL shows no total** — not monthly, not annualized.

5. **A "coming up / next N days" recurring list surfaced on Home**, separate from the recurring page. Copilot "Next Two Weeks" dashboard card (`copilot-community-02.md` L37,43). Rocket "Coming Up: 6 recurring charges due within the next 7 days for $377.30" (`rocket-money-community-02.md` L25,60,68). Simplifi Overview Summary + reminders (`quicken-simplifi-community-02.md` L27). **KEEL's Home has no upcoming-bills list**; its "Projected cash · next 30 days" card renders flat with duplicate axis labels because there are no confirmed recurring items (`keel-core-01.md` L36,71).

6. **Relative due-date countdown copy.** "in 27 days" / "in 6 days" (Rocket, `rocket-money-community-01.md` L25,77), "today"/"tomorrow"/"In 3 days" switching to "on Feb 6" past ~a week (Simplifi, `quicken-simplifi-community-03.md` L57,95), "around Dec 4th" (Copilot, `copilot-community-02.md` L29). **KEEL evidences no relative-countdown format.**

## Findings

### RECURRING-1 — No calendar / month-grid view of recurring due dates [P1]
- **Evidence:** `recurring-desktop.png`; `keel-money-02.md` L40-45. Competitors: `monarch-community-03.md` L46-64 (`community-x04/x05` calendar images), `quicken-simplifi-community-02.md` L27 + `-03.md` L58, `rocket-money-community-01.md` L27,52.
- **Competitors:** Monarch makes the calendar the *primary* Recurring view (tabs "Upcoming | All merchants" both sit above a month grid; chips stack in day cells with merchant + amount + confirmed-checkmark; a list table re-renders the same data below). Simplifi and Rocket use a dot-per-day density calendar (quiet grid; today outlined/filled; dots mark days with items). All three provide month paging + a "Today" jump. Mobile variants degrade to a mini-calendar of dots + list-below (Monarch `monarch-community-03.md` L58-64; Rocket mobile calendar icon in header).
- **KEEL today:** The page is a flat "Bills & scheduled" list section only. No calendar exists, and W1.1 (`PLAN-FEATURE-PARITY.md` L19-24) plans only "Active / Suggested / Paused / Upcoming-30d list" — a calendar is not even on the roadmap. This directly undercuts KEEL's stated value prop ("projects it into your balance curve") because the balance curve (Home projection) is the only forward-looking surface and it is degenerate when empty.
- **Fix:** Add a month-grid view (toggle or tab beside the list) rendering confirmed + projected occurrences as day-cell chips: merchant, signed amount, confirmed-checkmark vs projected-plain styling. Today marked with a badge; prev/next + "Today". On 390px, degrade to the Monarch/Simplifi dot-calendar + list-below pattern (dots only, details in the list). Reuse `recurring_occurrences` for placement.
- **Maps to:** W1.1 (extend — add calendar view), NEW calendar sub-slice.

### RECURRING-2 — No per-series detail view (cadence, next, amount history, matched transactions) [P1]
- **Evidence:** `recurring-desktop.png`; `keel-money-02.md` L109 (open question: "What does a detected recurring item card look like"). Competitors: `copilot-community-02.md` L17,29-32,88-89; `quicken-simplifi-community-03.md` L38-53; `monarch-community-03.md` L13,82,98.
- **Competitors:** Copilot's detail pane: category pill, "NEXT PAYMENT $1,984.00 / around Dec 4th", a Jan–Dec occurrence dot-timeline, a RULES section, "Key Metrics" yearly totals table (with explicit "$0.00" for zero years), Last Account Used, and a transactions sub-list scoped to that series. Simplifi's series modal: a 6-month per-month amount bar chart with an "Average $24" reference line, "Total in Last 6 months : $145", a "Coming Up" next-charge card, and a reverse-chron "History" list. Monarch's chip popover: cadence + last 3 matched charges + link to all N transactions.
- **KEEL today:** No detail route. A user cannot open a series to see its cadence, its next occurrence, which transactions matched it, or its price history. Backend has the data (occurrences, candidate versions, evidence) but nothing surfaces it.
- **Fix:** Add a series detail panel/route: header (merchant, cadence, NEXT occurrence amount+date), an occurrence history list (matched canonical transactions, each linkable to Ledger), and a small amount-over-time chart (bars per period + average line, Simplifi pattern). Respect Law 9 (as-of/scope footnote), Law 5 (raw memo shown, never actionable).
- **Maps to:** W1.1 (extend), NEW series-detail slice.

### RECURRING-3 — No paid / upcoming / due / overdue / missed occurrence states [P1]
- **Evidence:** `recurring-desktop.png`; `keel-money-02.md` L42 (subtitle "shows it as due" is the only status word). Competitors: `monarch-community-03.md` L77,87,95; `copilot-community-02.md` L25,44,85,94; `quicken-simplifi-community-02.md` L54,69; `quicken-classic-community-01.md` L42,66.
- **Competitors:** Confirmed-vs-projected is computed *per occurrence against actual bank activity* (Monarch: checkmark+colored chip = matched, plain = projected — same merchant shows both in one month). "Overdue" is a first-class label (Copilot, Quicken red exclamation). "Paid" is per-instance, not per-series (Simplifi: an item due "today" is Paid while a same-payee item due "tomorrow" is not). Quicken carries a 3-value taxonomy (Overdue / Auto / Due).
- **KEEL today:** No occurrence-status vocabulary is visible. KEEL's differentiator ("one click enters it into the ledger on the day") *requires* a due/entered/matched/missed state machine to be legible, but none is shown. Without a "missed"/"overdue" state, the app cannot tell the user a bill they expected did not arrive — a core trust function of a bills tracker.
- **Fix:** Define and render an occurrence status enum: Upcoming (projected, future), Due (window open), Matched/Paid (a real transaction reconciled to it — checkmark, adjacent to amount per Law 8), Overdue/Missed (past due, no match). Color: red reserved for negative money only, so use an amber/neutral pill + icon for Overdue, never red text on the status itself. Status sits adjacent to the amount it qualifies.
- **Maps to:** W1.1 (core), NEW occurrence-status model surfacing.

### RECURRING-4 — Single undifferentiated "Bills & scheduled" list; no Suggested vs Active vs Paused separation [P1]
- **Evidence:** `recurring-desktop.png` (one section, "Bills & scheduled"); `keel-money-02.md` L42,68. Competitors: `rocket-money-community-01.md` L17,32,78 (Upcoming / All Recurring / Calendar tabs; Subscriptions vs Bills sections); `copilot-community-02.md` L17,25 ("This month" / "In the future"); `quicken-simplifi-community-02.md` L18 (Overview / Cash Flow / All Recurring).
- **Competitors:** Everyone segments the set. Copilot splits "This month" vs "In the future" (each collapsible). Rocket splits Upcoming vs All and Subscriptions vs Bills & Utilities with independent counts/totals. Simplifi tabs Overview / Cash Flow / All Recurring. The AI-suggested-but-unconfirmed items are kept visually distinct from confirmed ones.
- **KEEL today:** One flat "Bills & scheduled" bucket. W1.1 *plans* Active/Suggested/Paused sections but the captured page shows none of that structure — and critically, KEEL's Law 2 (suggest→approve) means the Suggested-needs-approval set must be visually separated from Active-confirmed, yet the empty-state copy folds detection ("KEEL has detected") and manual entry ("+ Add", the "anything you know is coming" banner) into one section with no seam. A user cannot tell what needs their approval vs what is already live.
- **Fix:** Render (when populated) distinct sections: **Suggested** (confirm/reject, Class B approval per Law 11), **Active** (next-due, cadence, amount, pause/cancel), **Paused** (resume/cancel). Route suggestions through the typed-AI-response contract (verdict/confidence/evidence_refs/proposed_actions). Consider surfacing the suggested count as a Review-nav badge (W1.5).
- **Maps to:** W1.1.

### RECURRING-5 — No aggregate total (monthly or annualized) for the recurring set [P2]
- **Evidence:** `recurring-desktop.png`; `keel-money-02.md` L26 (KEEL notably omits totals on Budgets too — a pattern). Competitors: `rocket-money-community-01.md` L25,32,78; `copilot-community-02.md` L25; `quicken-simplifi-community-02.md` L27.
- **Competitors:** Rocket's list header is a status/context line — "10 SUBSCRIPTIONS · You spend $5,474/yearly"; mobile shows per-bucket annualized totals. Copilot shows a "left to pay / paid so far" progress ring plus yearly Key Metrics. Simplifi's Summary card totals Income/Expenses/Net for the window.
- **KEEL today:** No total anywhere on the Recurring surface. A subscriptions view whose headline question is "how much am I bleeding on recurring charges" answers it nowhere.
- **Fix:** Add a header status line: count + normalized monthly total + annualized total ("$X/mo · $Y/yr"), scoped and Law-9-footnoted (dominant currency, confirmed series only). If income recurring (paychecks) is co-listed, show expected-in vs expected-out separately (Simplifi's In/Out/Net split), income with +/green, outflow plain (red reserved for negative money per Law 8).
- **Maps to:** W1.1 (extend).

### RECURRING-6 — Home has no upcoming-bills list; the recurring→projection payoff renders as a broken chart [P2]
- **Evidence:** `keel-core-01.md` L36,62,71 ("Projected cash · next 30 days" flat band, four identical "15.2K" y-axis labels — flagged as looking like a chart-scaling artifact; caption "No confirmed recurring bills in the window yet"). Competitors: `copilot-community-02.md` L37,43; `rocket-money-community-02.md` L25,60,68,76.
- **Competitors:** Copilot's Home "Next Two Weeks" card and Rocket's "Coming Up" sentence ("6 recurring charges due within the next 7 days for $377.30") give a glanceable near-term obligations list on the landing surface. Rocket folds count+window+total into one plain sentence — a good model for KEEL's TLDR-first typed-response ethos.
- **KEEL today:** No upcoming-bills list on Home. The one forward-looking element, the projection chart, is degenerate (duplicate axis labels read as a rendering bug, not an intentional flat line) precisely because recurring is empty — so the flagship "recurring feeds your balance curve" loop currently produces a screen that *looks broken* to a new user. W2.5 (`keel_cash_flow_forecast`) is planned but "build if time allows."
- **Fix:** (a) When there are zero confirmed series, suppress the projection chart's numeric axis or render an explicit empty-state instead of a flat line with cloned tick labels (fixes the "looks broken" trust hit). (b) Add a Home "Coming up · next 14 days" list (merchant, due date, amount) sourced from confirmed `recurring_occurrences`, with a one-sentence rollup (Rocket pattern) above it. (c) Land W2.5 so the balance curve actually reflects confirmed bills.
- **Maps to:** W2.5; cross-ref dashboard fragment for the axis-label artifact.

### RECURRING-7 — No price-change detection/alert; amount-match tolerance is neither shown nor editable [P2]
- **Evidence:** `recurring-desktop.png`; gap report cites Simplifi "recurring/amount-matching" as a benchmark (`FEATURE-GAP-REPORT.md` L111). Competitors: `copilot-community-02.md` L31,93 (RULES chip "from **$1,388** to **$2,835**" = explicit tolerance band); `quicken-simplifi-community-03.md` L42-44,90-91,96 (per-month amount bar chart + "Average" reference line + itemized history; "Connect biller … keep Simplifi updated with your most recent bill information").
- **Competitors:** Copilot surfaces the amount-tolerance range as an editable natural-language rule chip, so the user sees and controls how much variance still counts as "the same bill." Simplifi visualizes amount drift over months against an average line and nudges connecting the biller to catch amount changes. Price-change alerting ("your Netflix went up") is a headline Rocket/Simplifi capability.
- **KEEL today:** `recurring_candidate_versions` presumably stores an amount range, but nothing surfaces the tolerance, lets the user adjust it, or flags when a new charge lands outside the historical band (a price increase). No price-history visualization exists. This is the exact "amount-matching tolerance" sub-dimension the founder called out — currently zero UI.
- **Fix:** (1) Surface the series' matching rule (name pattern, amount low–high, cadence, day-of-month window) as editable chips (Copilot pattern) in the series detail. (2) When a matched occurrence's amount exceeds the tolerance band, flag it as a price change (badge + a suggest→approve "update expected amount?" per Law 2), and log to audit. (3) Show a per-period amount chart with an average line in the detail view.
- **Maps to:** NEW (price-change detection + tolerance UI), depends on RECURRING-2.

### RECURRING-8 — No relative due-date countdown; due dates likely bare/absolute [P2]
- **Evidence:** `recurring-desktop.png`; `keel-money-02.md` L42 (subtitle only). Competitors: `rocket-money-community-01.md` L25,77; `quicken-simplifi-community-03.md` L57,95; `copilot-community-02.md` L29.
- **Competitors:** Due dates read as urgency-encoding relative phrases: "in 27 days", "in 6 days" (Rocket), "today"/"tomorrow"/"In 3 days" then switching to absolute "on Feb 6" past ~a week (Simplifi's explicit threshold rule), "around Dec 4th" for a fuzzy projected date (Copilot). The relative form is the status adjacent to the amount.
- **KEEL today:** No due-date format is evidenced; nothing indicates KEEL renders a relative countdown. KEEL already uses "MM-DD" bare dates in the Ledger (`keel-core-01.md` L47), suggesting a bare-absolute default that would read as low-urgency here.
- **Fix:** Render occurrence due dates as relative countdowns for near-term items (today / tomorrow / in N days), switching to absolute for distant ones, adjacent to the amount. For projected (unconfirmed-cadence) dates, use an approximate phrasing ("~Dec 4") to honor uncertainty.
- **Maps to:** W1.1 (copy/format detail).

### RECURRING-9 — Per-occurrence actions missing: no "skip this occurrence", no "mark paid", no "remove from list" [P2]
- **Evidence:** `recurring-desktop.png`; `keel-money-02.md` L109 (open question re: pause/cancel affordances); backend exposes only series-level confirm/pause/resume/cancel/reject (`FEATURE-GAP-REPORT.md` L20). Competitors: `rocket-money-community-01.md` L28,39,80 (kebab → Edit Details / Cancel [Name] / Remove From List / History); `monarch-community-03.md` L74,105 (per-row "..." → skip/mark-paid/edit implied); `quicken-simplifi-community-03.md` L68 ("Options"/kebab per occurrence).
- **Competitors:** Each recurring row/occurrence carries a kebab of granular actions. Two matter especially: **skip this occurrence** (a one-time gap — e.g. paused a month — without killing the series) and **mark paid / mark as reviewed** (manual reconciliation when auto-match fails). Rocket also cleanly separates "Cancel [merchant]" (act on the subscription) from "Remove From List" (stop tracking) — two non-equivalent operations.
- **KEEL today:** Only series-level lifecycle verbs exist; no per-occurrence skip/mark-paid, and no distinction between "stop tracking this series" and any merchant action. A user who wants to skip one month must pause/resume the whole series.
- **Fix:** Add a per-occurrence overflow menu: mark paid / matched, skip this occurrence, edit expected amount, view in ledger. Keep series-level actions (pause/cancel/reject) separate. Distinguish "Stop tracking" (delist) from any future cancellation helper (see RECURRING-10).
- **Maps to:** W1.1 (extend) + NEW occurrence-action procs.

### RECURRING-10 — "Cancel" verb collides with Rocket Money's cancellation-concierge meaning; no merchant-cancellation helper [P3]
- **Evidence:** `recurring-desktop.png` subtitle "confirm, pause or cancel them"; `keel-money-02.md` L42. Competitors: `rocket-money-community-01.md` L28,55-59,80-81; `rocket-money-iphone-01.md` L50,56-60 ("Start a cancelation" + self-service call/email/web icons).
- **Competitors:** In Rocket, "Cancel Netflix" means *Rocket contacts the provider on your behalf to end the subscription* — a distinct multi-step flow (pre-filled request form, consent checkbox authorizing representation, "We're on it!"). It is explicitly separated from "Remove From List." Rocket also offers a self-service fallback (phone/email/website channels) for users who don't want the concierge.
- **KEEL today:** KEEL's "cancel" almost certainly means "stop tracking this series" (a `recurring_series` status), not "cancel with the merchant." Users conditioned by Rocket will read KEEL's "cancel" as the concierge action and be confused or disappointed. Full concierge is out of scope for KEEL (Class D territory — acting on the user's behalf, representing them to a provider), and correctly so.
- **Fix:** (a) Rename the series-level verb to "Stop tracking" / "Archive" to avoid the collision; reserve "cancel" for anything that touches the merchant. (b) Optional differentiator that stays inside KEEL's laws: a non-Class-D "cancellation helper" that surfaces the merchant's known cancellation URL / support contact and a copyable cancellation note — information only, KEEL never transmits or represents the user. Frame per Law 10 (no money movement, no filing).
- **Maps to:** NEW (copy fix is trivial; cancellation-helper is a P3 differentiator).

### RECURRING-11 — Subscriptions vs bills/utilities not distinguished; no grouping by type [P3]
- **Evidence:** `recurring-desktop.png` ("Bills & scheduled" lumps everything); `keel-money-02.md` L42. Competitors: `rocket-money-community-01.md` L11,32,78 (mobile splits "5 SUBSCRIPTIONS" and "5 BILLS & UTILITIES", each with its own count + annualized total).
- **Competitors:** Rocket models subscriptions and bills/utilities as separate buckets with independent totals, letting a user reason about discretionary subscriptions (cancelable) vs fixed obligations (not) separately. Others at least separate income from expense recurring (Simplifi In/Out).
- **KEEL today:** One bucket, "Bills & scheduled", mixing a paycheck, rent, insurance, and a $2 subscription with no typing. KEEL's own banner even enumerates "Rent, insurance, a paycheck" as one undifferentiated set.
- **Fix:** Tag each series with a type (subscription / bill-utility / income) — derivable from category — and offer grouping/filter by type, with per-group subtotals. This also feeds the cancellation-helper (only subscriptions are meaningfully cancelable) and the income-vs-outflow total split (RECURRING-5).
- **Maps to:** NEW (small model + grouping toggle).

### RECURRING-12 — Detection is opaque: no per-series evidence/confidence, no "last run", no manual re-detect [P3]
- **Evidence:** `recurring-desktop.png` empty-state "Detection runs nightly"; `keel-money-02.md` L44,90,102,114 (praises the "Detection runs nightly" transparency but notes the empty state can't distinguish "not yet run" from "ran, found nothing"). Backend has evidence + confidence bps (`FEATURE-GAP-REPORT.md` L20). Competitors: `copilot-community-02.md` L31,93 (matching rule shown as editable chips = the "why we think this recurs" made visible); `quicken-simplifi-community-03.md` L40,86 ("Connect biller" contextual data-quality nudge per series).
- **Competitors:** Copilot exposes the exact match rule (name substring, amount band, day-of-month, cadence) so the user sees *why* something was grouped and can correct it. Simplifi attaches a per-series data-quality nudge.
- **KEEL today:** Detection is a nightly black box. The empty state can't tell "detection hasn't run against this data" from "ran and found nothing" (the census flags this ambiguity given Reports shows 54 transactions in the same dataset). No suggested series would show its evidence/confidence to justify itself, and there's no "run detection now" for an impatient user. KEEL's typed-AI-response law (Law 11: reason_codes, evidence_refs, confidence) is the natural home for this and is being left on the table.
- **Fix:** In the empty state, distinguish "no recurring patterns found yet" from "detection pending" (show last-run timestamp). For each suggested series, surface the typed-response fields: confidence, reason_codes, and the matched evidence transactions (TLDR-first, proof-on-demand). Add a manual "Check now" that enqueues detection.
- **Maps to:** W1.1 (surface typed-response fields) + NEW manual-trigger.
