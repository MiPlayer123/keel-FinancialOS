# Onboarding, import/export & empty states

## Convergent patterns
(≥3 competitors do these in this dimension; KEEL does not)

1. **A guided first-run onboarding sequence** — a short linear wizard that welcomes the user, then drives them to connect/add their first account, then confirms success. Simplifi (flows-flow-02: Welcome → Add accounts → Intuit consent, each with a single focused CTA and a decorative arrow pointing at it), Plaid Link's own 6-step wizard (flows-flow-01: consent → institution search → OAuth disclosure → bank login → select accounts → Success!), Rocket Money (flows-flow-03 Plaid handoff; iphone-05 "Add account" affordance), Monarch/YNAB (add-account landings). **KEEL has only a sign-in screen (`login-desktop.png`); on auth a user lands straight in a fully-seeded dashboard — there is no welcome, no orientation, no "connect your first account" moment, no progress/checklist.**

2. **Explicit data-sharing consent + scope disclosure before credential entry.** Plaid Link itemizes exactly what is shared ("account and routing numbers, account and balance info, contact details") on a pre-redirect screen (flows-flow-01 image 3); Simplifi shows an Intuit consent screen with three disclosure rows — "Data that's accessed / Your data is kept private / You're in control" (flows-flow-02 flow-15); Rocket Money shows the `cdn.plaid.com` handoff interstitial naming the destination app (flows-flow-03 flow-21). **KEEL's "+ Connect a bank" (`connections-desktop.png`) has no captured KEEL-side pre-consent, scope disclosure, or institution-search surface of its own.**

3. **Featured-institution picker with an escape hatch.** Copilot shows a curated 3×2 tile grid (Chase, BofA, Capital One, Amex, PNC, Fidelity, Apple, Venmo) plus "Link other institutions through Plaid" and "Not on Plaid? Try other ways to connect" (flows-flow-01 image 7); Plaid shows a searchable institution grid ("Search 11,000+ institutions", flows-flow-01 image 2); Rocket Money nests accounts under institution headers with per-institution actions (flows-flow-03 flow-20). **KEEL offers only a single "+ Connect a bank" button and a single "+ Add account" button on two different pages — no picker, no manual-vs-linked choice, no "other ways to connect."**

4. **Structured settings with named sub-sections/sub-nav.** Simplifi's settings has a labeled left sub-nav — General, Accounts, Businesses, Categories & tags, Notifications, All recurring, Rules, Spaces & sharing (flows-flow-02 flow-16); Monarch and Rocket Money route settings through a gear/More surface. **KEEL's Settings (`settings-desktop.png`) is one long single-column scroll of six stacked cards with no sub-navigation, anchors, or grouping.**

5. **File import with column mapping, format disclosure, and duplicate-handling reassurance.** Lunch Money: destination-account picker + dropzone + live "PROCESS 210 ROWS" count + a "Match CSV columns" step with per-field Required badges and "Do not import" (flows-flow-02 flow-09/flow-10). YNAB: File Import modal listing OFX/QFX (recommended) and QIF/CSV (supported) with a "Worried about duplicates? …duplicates are skipped" notice (flows-flow-02 flow-11). **KEEL exposes a bare "Import" button in the Ledger toolbar (`keel-core-01.md` §Controls) with no captured mapping step, format list, destination picker, row-count preview, or dedupe messaging.**

## Findings

### ONBOARDINGIMPORT-1 — No first-run onboarding; new users are dropped into a seeded dashboard with no guided setup [P1]
- **Evidence:** `login-desktop.png`, `dashboard-desktop.png`, `accounts-desktop.png`; census `keel-ops-03.md` (login has no post-auth flow), `keel-core-01.md`; competitor flows-flow-02 (Simplifi flow-13/14/15), flows-flow-01 (Plaid wizard), flows-flow-03 (Rocket Money).
- **Competitors:** Every competitor with a captured first-run runs a short linear wizard: Simplifi "Welcome to Simplifi / You're on your way…" → "Add accounts to see all your finances in one place" (single CTA, decorative arrow) → consent. Plaid Link is itself a 6-step progress-barred wizard ending in an explicit "Success!" screen. The pattern teaches the one next action and confirms completion.
- **KEEL today:** The only unauthenticated surface is `login-desktop.png` (email/password/magic-link/create-one). After auth the user lands directly on Home, already full of net-worth charts, cash-flow cards, and a projected-cash graph. There is no welcome step, no "connect your first account" landing, no setup checklist, and no success confirmation. For an AI-first system-of-record whose value depends on connected data, the highest-intent moment (first sign-in) is unguided.
- **Fix:** Add a first-run route gated on "household has zero connections/accounts": a 2–3 step wizard — welcome + one-line value statement → "Connect a bank or add an account manually" (reuse the Plaid Link launch already behind "+ Connect a bank", plus the manual path from W1.11) → success/next-step ("we'll categorize and detect recurring bills as transactions sync; detection runs nightly"). Keep it dismissible; show a lightweight setup checklist on Home until the first account exists.
- **Maps to:** NEW (depends on W1.11 add-manual-account; reuses existing Plaid connect flow).

### ONBOARDINGIMPORT-2 — Zero-data state is unhandled: Home/Reports assume seeded data and would render empty/degenerate charts for a real new user [P1]
- **Evidence:** `dashboard-desktop.png` (nine stacked chart cards), `reports-desktop.png`; census `keel-core-01.md` §States (the "Projected cash" chart already renders a degenerate flat band with duplicate "15.2K ×4" axis labels when there are no confirmed recurring bills), `keel-money-02.md`.
- **Competitors:** Simplifi's "Add accounts" empty state is a single illustration + one CTA (flows-flow-02 flow-14); onboarding gates the data-dense surfaces behind having accounts. Competitors never show a new user a wall of empty charts.
- **KEEL today:** KEEL's per-page empty states are strong where they exist (Review, Goals, Paychecks, Recurring, Statements, Reimbursements all have illustrated dashed-card "here's the next action" copy — a genuine KEEL strength). But the **data-dense Home dashboard and Reports have no evidenced empty/zero-account variant**; with the seed data removed, the "Free to spend," "Net worth · last 90 days," "Cash flow by month," and "Spending · last 30 days" cards have nothing to plot. The projected-cash card already demonstrates the failure mode: a flat line with repeated axis labels that "look like a chart-scaling rendering artifact" (`keel-core-01.md` §States).
- **Fix:** Give Home and Reports a first-run zero-state that replaces the chart grid with an onboarding prompt ("Connect an account to see your position") until there is data; guard every chart against min≈max/empty series (skeleton or "not enough data yet" copy, never a flat line with duplicated ticks).
- **Maps to:** NEW (pairs with ONBOARDINGIMPORT-1).

### ONBOARDINGIMPORT-3 — CSV export button is missing from "Export all data" despite Law 6 naming CSV as a guaranteed format [P1]
- **Evidence:** `settings-desktop.png` (Export all data card shows only JSON / QIF / Beancount); census `keel-ops-03.md` §Controls + §Open questions ("Why CSV is absent…"); CLAUDE.md Law 6 ("Full export always works … CSV/JSON/QIF/beancount"); `FEATURE-GAP-REPORT.md` #19 confirms the backend `packages/exports` already implements **csv**/json/qif/beancount.
- **Competitors:** Lunch Money accepts CSV import and treats CSV as the lingua franca; every competitor treats CSV as the baseline portable format.
- **KEEL today:** The Settings "Export all data" card ("Your full financial record, any time — the exit door is a feature. Choose a format:") offers JSON, QIF, Beancount — **no CSV button**, even though the exporter package already produces CSV. This is a pure UI omission that undercuts KEEL's headline Data Access Guarantee brand promise and violates the explicit format list in Law 6.
- **Fix:** Add the CSV button to the Export card (the backend format exists). While there, add one line naming what each format is for (CSV = spreadsheets, QIF/Beancount = other finance tools, JSON = full fidelity).
- **Maps to:** NEW (UI wiring of existing `packages/exports` CSV; Law 6 compliance).

### ONBOARDINGIMPORT-4 — "Disconnect" is irreversible (token crypto-shred) but styled as a neutral button with no confirmation and no negative color [P1]
- **Evidence:** `connections-desktop.png` (per-row "Disconnect", outlined/neutral, same weight as "Sync now"); census `keel-ops-03.md` §Controls ("text implies destructive/irreversible action but styled as a neutral button, not red"); `FEATURE-GAP-REPORT.md` #4 (disconnect performs "+crypto-shred").
- **Competitors:** Rocket Money styles institution removal as an underlined "Unlink" text link explicitly de-emphasized relative to the primary actions, and pins the destructive nature to institution scope (flows-flow-03 flow-20). Destructive account actions are consistently visually separated from routine ones.
- **KEEL today:** "Disconnect" sits inline, equal-weight, immediately beside "Sync now," with no confirmation modal captured and no destructive styling — yet the backend crypto-shreds the encrypted Plaid token, making it non-trivially reversible (the user must re-link and re-auth). One mis-click adjacent to the routine "Sync now" button can sever a connection.
- **Fix:** Require a confirmation dialog for Disconnect that names the institution and the consequence ("You'll need to reconnect and re-authorize to resume syncing; imported transactions are kept"), and visually de-emphasize/mark the action as destructive per the design-law reservation of weight for irreversible operations. Do not use red-for-money color, but do add a destructive treatment (e.g., a confirm step + secondary/muted placement).
- **Maps to:** NEW (relates to gap #4 disconnect saga — UI safeguard).

### ONBOARDINGIMPORT-5 — Connections only ever shows "active"; no reauth-needed / error / stale connection state or recovery path [P1]
- **Evidence:** `connections-desktop.png` (both rows "active"); census `keel-ops-03.md` §States + §Open questions ("Whether 'active' is the only Connections status value…"); `FEATURE-GAP-REPORT.md` #4 (backend has "reauth lifecycle").
- **Competitors:** Rocket Money surfaces per-institution sync recency and per-institution actions; Monarch shows per-account freshness ("11 hours ago", "1 minute ago") per row (monarch-appstore-01). Products that link banks universally surface a reauth/relink state when an item's credentials expire.
- **KEEL today:** Both connections render "active" with a to-the-second sync timestamp (a good trust signal). But there is no evidenced UI state for a Plaid item that needs re-authentication, has errored, or is stale — despite the backend already modeling the reauth lifecycle. When (not if) a Sandbox/real item expires, the user has no visible status, no CTA, and no recovery path from this screen.
- **Fix:** Add connection health states to each row — `active` / `reauth needed` (with a "Reconnect" CTA that relaunches Link in update mode) / `error` / `syncing` / `paused` — with status adjacent to the institution name (per the status-adjacency law), and surface a Review/Home badge when any connection needs attention.
- **Maps to:** NEW (surfaces existing gap #4 reauth lifecycle in the UI).

### ONBOARDINGIMPORT-6 — Import is a bare button: no column mapping, format disclosure, destination-account picker, row-count preview, or duplicate-handling copy [P1]
- **Evidence:** census `keel-core-01.md` + `keel-mobile-04.md` §Controls (Ledger toolbar "Import" button, no flow captured); `FEATURE-GAP-REPORT.md` (repo-shape lists `packages/imports` but notes "only `packages/ingest` exists"); competitor flows-flow-02 (Lunch Money flow-09/flow-10, YNAB flow-11).
- **Competitors:** Lunch Money: "Upload your files" → account destination pre-filled ("Lenny's Checking (Depository)"), dashed dropzone with an explicit constraint line ("CSV and PDFs supported. Rows must be < 10,000"), staged-file chip, and a primary CTA that injects the live row count ("PROCESS 210 ROWS"); then "Match CSV columns" with each CSV header as an in-place dropdown, Required/optional badges, and a "Do not import" option per column. YNAB: File Import modal states supported formats (OFX/QFX recommended, QIF/CSV supported) and proactively answers "Worried about duplicates? …Direct Import duplicates are skipped" with a "Don't show again" dismissal.
- **KEEL today:** The only import entry point is a single unlabeled "Import" button in the Ledger toolbar. No mapping, format list, destination selector, preview count, or dedupe reassurance is evidenced — and `packages/imports` doesn't exist yet. This is table stakes for a Quicken/Lunch-Money/YNAB migrator, and KEEL's own idempotency invariant (Law 9, "retry/replay can't duplicate an economic event") is exactly the reassurance YNAB surfaces at import time but KEEL doesn't.
- **Fix:** Build a real import flow: (1) destination-account picker + dropzone with a stated format+row-limit constraint line; (2) a column-mapping step over a live preview (date/description/amount/category), with Required badges and "Do not import"; (3) a pre-commit summary showing row count and how many are new-vs-duplicate (leveraging the existing dedupe spine), echoing the idempotency guarantee in copy. Support CSV first, then OFX/QIF (parity with the export formats).
- **Maps to:** NEW (`packages/imports` + Ledger/account import UI).

### ONBOARDINGIMPORT-7 — Local-dev credentials are rendered on the production-dated sign-in screen [P1]
- **Evidence:** `login-desktop.png` (bordered mono box: "Local dev: alex@keel.local / keel-local-dev-password"); census `keel-ops-03.md` §Open questions (flagged against CLAUDE.md secret-boundary law).
- **Competitors:** No competitor sign-in surface displays credentials; sign-in screens are minimal (email/password/SSO/magic-link).
- **KEEL today:** The sign-in page shows a hard-coded dev credential hint on a screen dated 2026-07-16 (production date). Even if these are non-secret dev fixtures, shipping a credential-shaped box on the auth screen reads as a leak, erodes trust at the very first impression, and risks a real secret being pasted there later. Law 12's secret boundary and taste bar both argue against it.
- **Fix:** Gate the dev-credential box strictly to non-production builds (env flag), and never render it on any deployed/production-dated surface. Confirm no real secret can ever populate it.
- **Maps to:** NEW.

### ONBOARDINGIMPORT-8 — Settings is one long single-column scroll with no sub-navigation or grouping [P1]

### ONBOARDINGIMPORT-9 — Audit-log ("Recent activity") leaks raw internal event names, shows un-deduped repeats, and has no filter/pagination [P2]
- **Evidence:** `settings-desktop.png` (Recent activity: "Auto-categorized new transactions · KEEL (automatic)" and "Decided a transfer match · You" mixed with verbatim "ingest.apply_action · KEEL (automatic)" repeated ~15× at the same minute); census `keel-ops-03.md` §Layout ("developer-facing string leaking into user-facing UI") + §States (dense, ungrouped, exact duplicates, runs past the fold, no "view all").
- **Competitors:** YNAB surfaces a bounded, human-labeled "Recent Moves" history (ynab-web-01). Audit/history surfaces are consistently humanized and bounded.
- **KEEL today:** The trust surface intended to prove append-only auditability instead shows a raw event key ("ingest.apply_action") next to humanized labels, ~15 identical consecutive rows, no grouping/collapse, and no filter, pagination, or "view all." It reads unfinished and undermines the "every change is recorded" trust message it's meant to convey.
- **Fix:** Map every event to a human sentence (no raw `snake_case` keys ever reach the UI), collapse runs of identical events ("Applied 15 imported transactions"), and add filter + pagination/"view all."
- **Maps to:** W1.10 (Settings: Activity card) — refine.

### ONBOARDINGIMPORT-10 — Connections rows don't show which accounts (or how many) each institution provides [P2]
- **Evidence:** `connections-desktop.png` (rows show only institution name + sync timestamp — "no money figures … purely connection/sync metadata", `keel-ops-03.md`); competitor flows-flow-03 flow-20 (Rocket Money nests accounts with masks/types under each institution).

### ONBOARDINGIMPORT-16 — Add-account entry points are fragmented and unlabeled (linked vs. manual is never offered as a choice) [P2]
- **Evidence:** `accounts-desktop.png` ("+ Add account" on Accounts), `connections-desktop.png` ("+ Connect a bank" on Connections); census `keel-core-01.md` §Open questions ("What 'Add account' opens — modal vs full-page, and whether it leads to Plaid Link"); `PLAN-FEATURE-PARITY.md` W1.11 (manual account create is live but its placement/UX unspecified); competitor flows-flow-01 image 7 (Copilot "Link other institutions through Plaid" + "Not on Plaid?
