# Transactions register & detail

Scope: the Ledger register (columns/density/filters/search/sort/group/bulk), the per-transaction
detail/edit surface, the SPLIT editor, notes/tags/attachments, pending/cleared/reconciled state,
original-vs-display merchant, and keyboard interactions. Ground truth for "KEEL today" = `ledger-desktop.png`,
`ledger-mobile-390.png`, and census `keel-core-01.md` / `keel-mobile-04.md`. KEEL's register is safe and
arithmetically honest (sign+color, transfer legs linked, footer totals over the full filtered set) — so there
is no true P0 here; the gaps are daily-driver friction and missing depth that every mainstream competitor ships.

## Convergent patterns
(≥3 competitors do this in this dimension; KEEL does not)

1. **A split editor with a live "left-to-split" remainder.** Copilot (`copilot-community-01.md` images 04/05: Equal/Custom tabs, "Left to split $0.00" green when balanced), Simplifi (`quicken-simplifi-community-02.md` community-09: "LEFT TO SPLIT $37.12", "+ Add Split", "+ Add Left To Split" auto-fill, "Delete all splits" ≠ "Cancel"), Monarch (`monarch-appstore-01.md` img05 ACTIONS → "Split transaction"), plus YNAB/Quicken splits. KEEL has no split at all — W2.4 deferred, "designed, not built" (`PLAN-FEATURE-PARITY.md` lines 81-86, 136-138).
2. **Per-transaction receipt/attachment.** Simplifi ("Attachments … ☁ Upload" → removable chip "Walmart Receipt.png", `quicken-simplifi-community-02.md` x05/x06), Monarch ("Add attachment", `monarch-appstore-01.md` img05), YNAB (dedicated receipt/image column in the register grid, `ynab-community-01.md` line 17/22), Ramp (Receipt column + "Auto-verified" amount/date/merchant checks, `ramp-community-01.md` img06), Quicken (paperclip column, `quicken-classic-community-01.md` img2). KEEL: nothing — no attach affordance, no receipt column, no indicator.
3. **User tags on a transaction, distinct from category.** Copilot ("Tags / + Add tag", `copilot-community-01.md` line 27), Simplifi ("Tags" dropdown, `flows-flow-02.md` flow-12), Monarch ("TAGS" pills with colored dots "Tax", "Reimburse…", `monarch-appstore-01.md` img05), YNAB (colored flag column). KEEL exposes no tag concept anywhere in the register or edit surface.
4. **A dedicated transaction-detail view (panel/modal), not just an inline field poke.** Copilot right-hand detail pane (`copilot-community-01.md` img01/03), Simplifi "Transaction detail" modal with ~13 fields (`quicken-simplifi-community-02.md` x05), Monarch review card (`monarch-appstore-01.md` img05), Ramp approval detail (`ramp-community-01.md` img03). KEEL's only per-row affordance is a pencil that opens an edit dialog (category picker + name/note per `PLAN-FEATURE-PARITY.md` W1.4); no screenshot shows a full detail surface with account/date/status/split/notes/tags/attachments together.
5. **A per-transaction cleared/reconciled status separate from posted.** YNAB (Uncleared / Cleared / Reconciled as filterable per-row states + Cleared+Uncleared=Working balance strip, `ynab-community-01.md` lines 22/59/61), Quicken (the "c" column + reconcile dialog, `quicken-classic-community-01.md` img2/img3), Monarch/Copilot ("Reviewed" / "To Review"). KEEL's only per-row status is "PENDING" on the two newest rows (`keel-core-01.md` line 47); cleared/reconciled lives only at the period level (Statements), never on the row.
6. **A bulk-action bar richer than one field.** Copilot ("N selected" → Category, Review, Type, ⋯, `copilot-community-01.md` line 38), Monarch, YNAB (checkbox column + File Import/More toolbar), Ramp (select-all + "Mark Ready"/"Sync (n)"). KEEL has "Select" → bulk categorize only (`PLAN-FEATURE-PARITY.md` W1.3); no bulk exclude/merge/tag/delete/mark-reviewed.

## Findings

### LEDGERTRANSACTIONS-1 — No split editor; a single charge cannot be categorized to more than one category [P1]
- **Evidence:** `copilot-community-01.md` (images 04/05/06), `quicken-simplifi-community-02.md` (community-09), `monarch-appstore-01.md` (img05), `PLAN-FEATURE-PARITY.md` lines 81-86 & 136-138; KEEL register `ledger-desktop.png` shows one immutable category pill per row.
- **Competitors:** Copilot: modal with "Equal split" / "Custom split" tabs, per-leg editable name + category (or an "EXCLUDED" pseudo-category), live "Left to split" turning green at $0.00, and the saved split surfaces back on the detail as a first-class field "🔀 $100.00 split 4 ways" plus a sibling-legs list. Simplifi: "LEFT TO SPLIT" running remainder, "+ Add Split" and "+ Add Left To Split" (auto-fills the remainder), a full Most-Used/All-Categories picker per leg, and "Delete all splits" as a distinct control from "Cancel". Both preserve the original as a read-only header.
- **KEEL today:** No split anywhere. Every row carries exactly one category dropdown pill (`keel-core-01.md` line 47). A real Amazon/Costco charge that is part groceries, part household can only be miscategorized whole — which also poisons Budgets, Reports, and the ≥85% categorization harness. W2.4 was deferred because "N offsets currently multiply rows × full amount" in the rich read model (`PLAN-FEATURE-PARITY.md` line 138) — a read-model bug, not a design objection.
- **Fix:** Build the split editor on top of `keel_cmd_manual_transaction`/balanced-batch (Σ=0 already enforced): a panel that keeps the original amount as a read-only anchor, N legs each with category + amount + optional exclude flag, a live "Left to split" remainder that must reach 0 to save (Σ invariant makes this free to validate), and an "Add remaining" convenience. Fix the rich read model first so split legs don't multiply the row.
- **Maps to:** W2.4 (unblock the read model; ship it).

### LEDGERTRANSACTIONS-2 — Register is dominated by raw ACH/memo strings with no normalized display name [P1]
- **Evidence:** `keel-core-01.md` line 52 ("ORIG CO NAME:DEEPTUNE CO ENTRY DESCR:PAYROLL SEC:PPD ORIG ID:9117571000", "REAL TIME TRANSFER RECD FROM ABA/CONTR BNK-021000021…", "FID BKG SVC LLC MONEYLINE Z347266911HG4B8"), `keel-mobile-04.md` line 45 (truncated "ORIG CO NAME:D…", "TST*THE KATI ROL…", "UEP*YOZ SHANGH…"), line 76 ("no cleaned/normalized display name is shown alongside the raw string"); `ledger-top.png` crop confirms the raw string is the bold primary label.
- **Competitors:** Copilot renders a normalized merchant as the primary label and keeps the original in detail (`copilot-community-01.md`). Simplifi rules can match on "Original statement name" vs "Quicken name," implying a cleaned display name exists on the row, with the raw string preserved and matchable (`quicken-simplifi-community-02.md` lines 60, x02). Quicken renaming rules do the same. Normalization is universal; the raw string is demoted to a detail field, never the scannable label.
- **KEEL today:** The bold primary text alternates between clean ("Panda Express", "Lyft") and unreadable machine strings row-to-row (`keel-core-01.md` line 52 "Normalization is visibly inconsistent row-to-row"). On mobile these truncate mid-token to garbage ("UEP*YOZ SHANGH…"). Law 5 correctly keeps ingested text data-tier, but that argues for *displaying a derived name on top*, not for putting the raw memo in the primary slot. W2.1 rule-renames exist but are not detection-driven, so most rows stay raw.
- **Fix:** Add a deterministic normalized display name (merchant cleanup pass, source='auto', never overwriting user/rule renames), render it as the primary label with the raw string demoted to a muted secondary line / detail field. Keep an "original description" reveal on the row (KEEL already keeps the affordance in the edit dialog per W1.4 — surface it inline). This is the single biggest legibility win in the register.
- **Maps to:** W2.1 (extend to a detection-time merchant-normalization overlay), NEW (register display-name rendering).

### LEDGERTRANSACTIONS-3 — Mobile has no way to recategorize or edit a transaction [P1]
- **Evidence:** `PLAN-FEATURE-PARITY.md` W1.4 ("mobile has no recategorize path — inline picker is sm+ only"); `keel-mobile-04.md` lines 45, 58 (rows show "Account · Category" as static gray text, "implicit per-row tap-to-open (no chevrons drawn)"), line 89 open question "What happens when Ledger's 'Select' button is tapped … not shown."
- **Competitors:** Monarch's entire transaction flow is mobile-first — a full review card with category pills, tags, notes, split, attach, delete, and a swipe-to-review gesture (`monarch-appstore-01.md` img05). Copilot, Simplifi, YNAB, Quicken all edit categories on phone. Editing on the phone is table stakes.
- **KEEL today:** On the 390px ledger the category is baked into a truncated "Account · Category" subtitle with no dropdown; the desktop inline category pill is explicitly gated to sm+ only. There is no evidenced tap target that opens an editor. The daily "fix this category on the go" loop is impossible on the device most people use.
- **Fix:** Make the whole mobile row tap-to-open a bottom-sheet detail (category picker, name/note, exclude, later split/attach). At minimum a category bottom-sheet on tap. Design law §8 (usable at 390px) makes this a compliance gap, not a nice-to-have.
- **Maps to:** W1.4 (extend the edit dialog to a mobile bottom sheet).

### LEDGERTRANSACTIONS-4 — Filters are coarse: no status/uncleared/needs-category/amount filter and no saved views [P1]
- **Evidence:** KEEL toolbar = Search + "All time / All accounts / All categories / Newest first" + "Group by: None" (`ledger-top.png`, `keel-core-01.md` lines 45-46). Compare `ynab-community-01.md` lines 17, 22, 32-33, 71.
- **Competitors:** YNAB's register search is a query-builder-as-autocomplete: typing "is" surfaces "Is: Uncleared / Cleared / Reconciled / Unreconciled / Cleared or Reconciled / Approved / Unapproved / Needs Category…", each with an icon, and a "Some transactions are hidden … View All" escape hatch. Ramp exposes amount/verified/flagged filter toggles and 349-row pagination (`ramp-community-01.md` lines 48-51). Copilot has a dedicated "☰ Filter" button. The recurring ask is filter-by-status and filter-by-uncategorized, plus reusable saved views.
- **KEEL today:** Four fixed dropdowns and a free-text search. No way to isolate "uncategorized," "pending/uncleared," "needs review," an amount range, tagged, has-attachment, or "flagged." No saved/named views. For 167+ transactions this forces manual scanning to find the rows that need work.
- **Fix:** Add filter facets for category-state (uncategorized/needs-review), status (pending/cleared/reconciled once #7 lands), amount range, account(s) multi-select, and text; persist filter+sort+group combinations as named saved views. A "N hidden by filter — Show all" banner (YNAB pattern) prevents the "where did my rows go" confusion.
- **Maps to:** W1.2 (extend beyond date presets to status/uncategorized facets), NEW (saved views).

### LEDGERTRANSACTIONS-5 — Bulk edit is category-only; no bulk exclude, tag, merge, delete, or mark-reviewed [P1]
- **Evidence:** `PLAN-FEATURE-PARITY.md` W1.3 ("multi-select … one category applied to N rows"); `keel-core-01.md` line 94 open question (bulk bar not captured). Compare `copilot-community-01.md` line 38.
- **Competitors:** Copilot's selection bar exposes "N selected" + Category + Review + Type + overflow. Monarch and YNAB add flag/attach/delete/approve in bulk; Ramp bulk-marks rows "Ready". Bulk is where cleanup after a sync actually happens.
- **KEEL today:** The "Select" toggle leads (per plan) to a single bulk action: apply one category. No bulk exclude-from-reports, bulk tag (blocked by #3-tags), bulk mark-reviewed/cleared, bulk delete of manual rows, or bulk transfer-mark. The selection UI's whole value is throughput; one action leaves most of it on the table.
- **Fix:** Expand the selection action bar to Category, Exclude, Tag, Mark reviewed/cleared, Merge (for a split-out or dup pair), and Delete — each routed through the existing audited command path, each undoable.
- **Maps to:** W1.3 (extend action set).

### LEDGERTRANSACTIONS-6 — No unreviewed-transaction count/queue; the "Review" surface only holds AI suggestions [P2]
- **Evidence:** `keel-core-01.md` lines 17, 56-58 (Review page = "Approve or dismiss what the AI suggests," empty), `keel-mobile-04.md` line 75 (Review scoped to "Recurring series, transfer matches and categorizations" only); `PLAN-FEATURE-PARITY.md` W1.5 ("Review badge = suggested transfers + recurring count").
- **Competitors:** Copilot puts a "16" needs-attention badge directly on the Transactions nav item and a "To Review" state per transaction (`copilot-community-01.md` lines 15, 55). Monarch runs a finite decrementing review queue ("4 remaining") with swipe-to-review (`monarch-appstore-01.md` line 19, img05). Both make "new transactions you haven't looked at" a first-class, countable backlog.
- **KEEL today:** There is no "unreviewed transaction" concept in the register — only "PENDING" (a bank state) and a Review page limited to AI suggestions. New synced rows land silently in the list with an auto-category and no needs-your-eyes marker or count. The planned Review badge counts suggestions, not freshly-imported transactions.
- **Fix:** Add a per-transaction reviewed/unreviewed flag (auto-categorized rows start unreviewed), a count badge on Ledger/Review, an "Uncategorized/Needs review" filter (see #4), and a keyboard/swipe "mark reviewed" so the sync→triage loop has a defined end.
- **Maps to:** W1.5 (extend badge to unreviewed txns), NEW (reviewed flag + queue).

### LEDGERTRANSACTIONS-7 — Only "PENDING" exists as a row status; no cleared/reconciled marker on the row [P2]
- **Evidence:** `keel-core-01.md` lines 47, 77 (PENDING only on 2 newest rows); `ynab-community-01.md` lines 22, 32, 59-61; `quicken-classic-community-01.md` img2 ("c" column) & img3 (reconcile).
- **Competitors:** YNAB carries per-row cleared/uncleared (a togglable "C" circle) plus a Cleared+Uncleared=Working balance strip, and reconciled as a lock state. Quicken's register has a "c" cleared column and a reconcile dialog computing Cleared vs Statement Ending vs Difference=0.00. The row itself tells you whether the bank has confirmed it and whether it's been reconciled.
- **KEEL today:** The register shows "PENDING" vs nothing. KEEL *has* strong period-level reconciliation (Statements, gate 8 GREEN) but that status never appears on the transaction row — a reconciled row and an unreconciled one look identical in the ledger. Users can't scan for "not yet cleared" or "already locked."
- **Fix:** Surface a compact per-row status glyph adjacent to the amount (pending / cleared / reconciled-locked), sourced from provider posting + the existing statement/period-lock model; make it a filter facet (#4). Reconciled/locked rows should visibly signal that they're immutable (ties to Law 2 period locks).
- **Maps to:** NEW (row-level status derived from statements/period_locks + Plaid pending).

### LEDGERTRANSACTIONS-8 — No per-transaction attachments/receipts [P2]
- **Evidence:** `quicken-simplifi-community-02.md` x05/x06, `monarch-appstore-01.md` img05, `ynab-community-01.md` line 22, `ramp-community-01.md` img06; KEEL gap #20 in `design/FEATURE-GAP-REPORT.md` (Missing).

A receipt icon on the row signals "documented."
- **KEEL today:** No attach action, no receipt column, no per-row receipt indicator. Supabase Storage exists but is unwired (gap #20). For an entity/LLC system-of-record this is load-bearing (audit, Schedule C substantiation).
- **Fix (UI specifics beyond the known capability gap):** Add an attachment affordance in the detail surface (drag/drop + upload), render a removable chip per file, and put a small paperclip/receipt icon *in the register row* (a scannable column like YNAB/Quicken) so "has receipt" is visible without opening the row. Keep OCR/receipt-match (≥90% gate) as a later layer.
- **Maps to:** NEW (gap #20 — this finding adds the register-column + chip UI, not just "wire storage").

### LEDGERTRANSACTIONS-9 — No exclude-from-reports / exclude-from-budget toggle on a transaction [P2]
- **Evidence:** `quicken-simplifi-community-02.md` lines 67, 77 & x05 (two independent checkboxes: "Spending Plan" and "Reports", each with a one-line blast-radius caption); `copilot-community-01.md` line 64 (per-split EXCLUDED pseudo-category); `monarch-appstore-01.md` img06 (refund/credit rows net negative into a category).
- **Competitors:** Simplifi models exclusion as two separate booleans — exclude from budget math vs exclude from reports/watchlists — each spelled out ("Affects Spending Plan calculations." / "Affects Reports, Watchlists, and Upcoming Summary."). Copilot lets a single split leg be EXCLUDED. This is how users keep a reimbursed cost or a one-off out of their trends without deleting it.
- **KEEL today:** No exclude concept on a transaction. The only exclusion is the systemic "confirmed transfers excluded" rule surfaced in Reports footnotes (`keel-money-02.md` line 57). A user can't mark "this $4,518 CC payment / this reimbursed dinner shouldn't count in my spend" — which is exactly the modeling gap that makes the dashboard call a Discover bill payment the "Top merchant" (`keel-core-01.md` line 80).
- **Fix:** Add per-transaction (and per-split-leg) exclude flags with explicit scope (budgets vs reports), each captioned with its blast radius, each feeding the pinned scope/formula-version metadata (Law 9). Consider it a prerequisite for trustworthy Reports/Budgets.
- **Maps to:** NEW (extends W2.2 budgets + reports scoping).

### LEDGERTRANSACTIONS-10 — Register has no column headers and no density/column controls [P2]
- **Evidence:** `keel-core-01.md` line 47 (columns conveyed by position only), `keel-mobile-04.md` line 49 ("No column headers … conveyed by position/typography only"); `quicken-classic-community-01.md` img1 (Date/Payee/Category/Payment/Amount/Balance headers, sortable), `ynab-community-01.md` line 17 (checkbox/flag/receipt/Date/Payee/Category/Memo/Outflow/Inflow/status headers).
- **Competitors:** Quicken and YNAB present an explicit, sortable, sometimes user-configurable column header row (Quicken's column set even varies per account: Memo/Tag/attachment/"c" columns, `quicken-classic-community-01.md` line 24). Headers make sort direction, what's sortable, and what each column *is* legible at a glance.
- **KEEL today:** No header row on desktop or mobile; sort is a "Newest first" dropdown divorced from any column; there's no way to add a memo/tag/balance/status column or change density. A first-time user must infer that the right-hand number is the amount and the pill is the category.
- **Fix:** Add a lightweight sortable header row on desktop (Date · Merchant/Account · Category · Status · Amount), click-to-sort with a direction caret, and (later) optional columns (running balance for account view, tags, receipt, memo). Keep it calm — thin stone borders, not a spreadsheet.
- **Maps to:** NEW.

### LEDGERTRANSACTIONS-11 — No keyboard interactions in the register [P2]

- **Fix:** Add register keybindings (j/k navigate, x select, c open category typeahead, e edit, / focus search, enter open detail) with discoverable hints; make the category picker a type-to-filter combobox with inline create (Copilot pattern).

### LEDGERTRANSACTIONS-17 — Category pill on a transfer-matched row is relabeled but its interactivity is ambiguous [P3]
- **Evidence:** `keel-core-01.md` lines 49, 90, 95 (transfer rows show "⇄ Transfer ←/→ [account]" instead of a category pill; open question: "genuinely disabled/locked … or just relabeled while still editable").
- **Competitors:** Copilot exempts transfer rows from the category system entirely and marks them with a "T" row-type glyph (`copilot-community-01.md` lines 25, 71); the row visibly reads as system-linked, not a free choice.
