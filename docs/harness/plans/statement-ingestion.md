## 1. Design decisions
1. **Reuse, don't fork.** Upload = existing document routes with `kind='statement'`. Staging mirrors receipts: immutable typed extraction row + mutable suggest→approve decision row. Approval materializes into existing `statements`/`statement_lines` via existing validation — extraction never touches canonical tables directly (Laws 5, 2/10 class B).
2. **Statements need their own staging tables.** `document_extractions` is receipt-shaped. New `statement_extractions` (+ typed child line/holding tables, BIGINT columns not money-in-jsonb — Law 4) and `statement_drafts` (decision row). No parallel upload pipeline invented.
3. **Deterministic parsers first-class.** CSV + OFX/QFX parse with pure hand-rolled TS in `packages/documents` (no new deps; vendor bundle already ships `@keel/documents` to worker). PDF via AI extractor in `packages/ai` (fixture default; cloud wiring a human ⚑). Both land in same staging tables with `extractor` provenance + confidence (deterministic=1.0, AI=clamped model-reported). Both still suggest→approve.
4. **Idempotency (Law 9):** same bytes → same sha256 → version unique no-ops; one extraction per `(version, extractor, extractor_version)`; one draft per version; approved statement uses file sha256 as `statements.source_hash` → existing unique key blocks dupes across re-uploads; confirm-upload returns `duplicate:true` when a statement-kind version with same hash exists.
5. **Account binding explicit at upload** (required in upload dialog, stored on draft). Extractor's institution/mask read kept as inert *hint* used only to warn on mismatch (explicit ownership, Law 9 §9.1).
6. **Card-payment linking** = deterministic matcher (Law 1) → class-B suggestions in `statement_payment_links`: for a liability-account statement, find card-side inflow within `[period_end, period_end+35d]` equal to `|ending_minor|` (exact first; in-window candidates lower-scored; prefer existing `transfer_links` pairs). Confirm/reject/detach mirrors `document_transaction_matches`.
7. **Investment statements** → positions in `statement_extraction_holdings`; approval for investment-subtype account offers separate class-B `statements.apply_holdings` writing `holdings` with new `source='statement'` at `as_of=period_end` (idempotent). Discrepancies vs current = read-model diff, never auto-corrected.
8. **Contract amendments (log in NOTES.md):** investment/PDF statements can't satisfy strict `opening+Σ=ending` → add `statements.balance_check` (`'strict'` default | `'anchor'`); relax `CreateStatementPayloadSchema.lines` min1→min0 and `CloseReconciliationPayloadSchema.items` min1→min0 only when zero lines. Default strict behavior unchanged.

## Codex Review v1 (2026-07-19) — VERDICT: MUST CHANGE FIRST

12 required amendments before build (security/correctness/maintainability = fail). Summary — full detail drove the v2 revision:
1. **Enforceable Law 5 capability boundary**: a narrow typed `StatementJobIO` port (resolve version metadata → download fixed object → one fixed extractor endpoint → exactly `keel_worker_persist_statement_extraction`); parsers/core get only bytes, never Supabase/`fetch`/`.rpc`/`.from`/Storage. 2. **Expanded red-team matrix**: hostile filenames, CSV headers, debit/credit columns, OFX NAME/security fields, and a real injection-bearing PDF — assert no network/tool/RPC/canonical-write before approval. Fix the impossible "byte-identical into statement_lines" claim: byte preservation lives in the immutable original/raw_evidence; canonical boundary is deterministic reject-or-truncate (500-char cap).
3. **Separate attach vs ingest**: discriminated contract (`mode='attach'` target required no draft / `mode='ingest'` accountId required, draft created); make `statement_drafts.account_id` NON-NULL for ingest; stop the existing attachment UI from creating drafts.
4. **Real tenant-scoped content identity**: current chain does NOT dedupe re-uploads (new documentId each time). Add a tenant `document_hashes` registry, bind `source_hash` from the server version only (never the approval payload), add economic uniqueness `(household_id, account_id, source_hash)`, lock draft against transitions out of approved/dismissed.
5. **Approval tokens (Law 11) — do not exist yet; must be built**: one-use expiring token binding exact normalized payload+actor+household+account+version+draft+proposal version; test tamper/replay/expiry/wrong-actor/wrong-scope. Share ONE internal SQL validate/materialize routine between manual create and draft approval (no copy).
6. **Zero-line/anchor explicit in SQL**: `balance_check NOT NULL DEFAULT 'strict'`; `coalesce(sum,0)` so empty≠NULL bypass; anchor only for eligible investment/valuation source with typed reason + stored gap explanation (gate 8); server-side amount/currency/period/one-txn-per-line validation for matched_transaction (today only a UI heuristic); UI supports zero lines + account currency (not hardcoded USD).
7. **Complete deterministic payment-matcher**: pick V1 exact-only OR explicit allocations with aggregate-capacity invariant; define subtype/sign/currency/status/window inclusivity/score+version/tie-break/ambiguity threshold/reason codes; never auto-confirm; reuse keel_detect_transfers + never resurrect rejected links + never call keel_decide_transfer(true) from payment approval; add API map for "Find payment".
