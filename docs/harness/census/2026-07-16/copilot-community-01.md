## Information architecture
- Left global nav (dark macOS shot, image 01) top-to-bottom: **Dashboard, Transactions** (badge "16"), **Accounts, Investments, Categories, Recurrings**. Below a divider: **MY ACCOUNTS** section grouped into collapsible sub-headers **Credit Cards ▾**, **Depository ▾**, **Investment ▾**, each listing individual linked accounts with a colored status dot and live balance. Bottom-of-sidebar utility links: "Explore macOS", "Get help", "Settings" — utility/meta items visually separated from primary nav.
- Transactions is one click from the sidebar and carries a numeric badge (16) — read as an unreviewed/needs-attention count given the badge sits directly on the "Transactions" label and the center pane's default view is "All Transactions" with review affordances everywhere.
- Categories (image 07/08) is a sibling top-level nav item to Transactions, not nested under it, and its center-pane list is itself hierarchical: parent groups (e.g., "Food & Drink", "Shopping", "Car & Transport", "Home") expand via a disclosure triangle (▾) to child categories (e.g., Food & Drink → Restaurants, Groceries). A small numeric badge next to the parent name (e.g., "2") gives the child count without expanding.
- Selecting a transaction row surfaces its full detail one click away, as a right-hand panel in the desktop layout (image 01) or as its own screen in the narrower layout (images 03, 06).
- From a transaction detail, "Split" is one click away via a "Split" button (image 01/03 header) which opens the "Split Transaction" modal (images 04/05); once saved, the detail view exposes an "Edit split" action and a "Split" summary row (image 06) that is itself a further one-click entry back into the split editor.
- Category drill-down (image 07/08 right pane) is reached by clicking a category/group row from the left list; the right pane's content is scoped to whatever was clicked ("Food & Drink" in image 07, "All Regular Categories" — i.e., no specific selection / rollup view — in image 08).
- "Excluded Categories" (image 07) is a visually separate list section below "Regular Categories", implying a top-level partition between categories that count toward budgets and ones that don't (only "Work Expenses" shown there, $5, no budget bar).

## Layout & content

- **Transaction list rows** (images 01, 07 bottom, mirrored pattern in 02): `[checkbox] Merchant  AccountName(dim)  [category pill]  $Amount  ⋮`. ## Flow steps
1. Do: user checks a transaction in "To Review" state (e.g., "Starbucks", image 02) → See: a category-picker popover opens on the row itself (no navigation away), pre-populated with the current (evidently wrong) category shown crossed out, and a live-filtered list of matching categories plus a "New category" escape hatch.
2. Do: user opens a transaction's detail and clicks "Split" (button visible in 01/03 header) → See: "Split Transaction" modal (04) opens with the transaction summarized read-only at top and defaults to "Equal split" mode with (at minimum) 2 legs at 50%/50%.
3. Do: user switches to "Custom split" tab and adjusts allocations (05) → See: each leg's dollar amount and percent update live; a running "Left to split" total at the bottom reads "$0.00" (shown in green) once the legs sum back to the original amount, and only then would Save be expected to be meaningful (no error/blocked state was captured in evidence).
4. Do: user saves a split and returns to (or later re-opens) the transaction detail (06) → See: the detail view now shows a "Split" field summarizing "🔀 $100.00 split 4 ways" with a chevron, plus a header-level "Edit split" shortcut, plus a "Split transactions" list of the sibling legs below the main fields — i.e., the split is not hidden, it's surfaced as a first-class field plus a supplementary list.

- **Pre-tracking period on trend chart** (image 08): early months on the horizontal bar-chart trend are rendered as a flat dashed line rather than solid bars, read as "no budget/tracking data yet" for those months, distinct from the "$0.00" values found in the Key Metrics table for years with literally $0 spent per year (2020 in image 07, 2023 in image 08) — i.e., two different empty-state treatments for "no data" depending on whether it's a chart or a table.
- **Fully-allocated split**: "Left to split  $0.00" rendered in green (04/05) — the only "success"-toned state text captured for the split flow; no error/over-allocated/under-allocated state was captured in evidence.

## Business rules implied
- A transaction can be reviewed, split, and/or marked recurring independently — all three are separate header buttons on the same detail view, not a linear wizard (image 01/03).
- Splitting a transaction preserves the original transaction as a read-only reference (shown at the top of the split modal) while generating N child legs that each carry their own category (or "Excluded") and must sum back to the original amount, tracked live via "Left to split" (images 04/05).
- A split leg can be individually excluded from categorization via an "EXCLUDED" pseudo-category distinct from real categories (04/05/06) — exclusion is a per-leg property, not all-or-nothing for the parent transaction.
- Transfers between the user's own accounts ("Online Banking Transfer From/To ...") are exempted from the categorization pill system entirely (image 01) — they show no category pill at all, unlike every other row.
- Category budgets support a parent/child rollup: a group like "Food & Drink" has its own aggregate spent/budget figures independent of, but composed from, its children "Restaurants" and "Groceries" (images 07/08) — a child can be over its own budget (Restaurants $223/$200) while the parent group is still under its rollup budget ($385/$450).
- Some categories are explicitly outside the regular budget system ("Excluded Categories" section, image 07, containing "Work Expenses") — they display a spent figure ($5) with no budget bar/comparison at all, implying they're tracked but not compared against a budget target.
- Historical per-year "Total spent per year"/"Average monthly spend" metrics show "$0.00" for years predating the account's data (2020 in image 07, 2023 in image 08) rather than omitting the year or showing "N/A" — zero is used as the literal not-yet-tracked value in this table.

## Standout details
- Small square glyph badges ("T", "R") prefixing certain merchant names in the transaction list (image 01) — "T" appears only on the two "Online Banking Transfer" rows, "R" appears on "Expensify" and (image 02) "Hulu" — read as compact, at-a-glance row-type markers (transfer vs. recurring) that don't require opening the row to learn the row's nature.
- The category quick-edit popover (image 02) shows the *previous* (wrong) category pill crossed out/dimmed directly above the typeahead input while the user retypes — giving a visible "what you're replacing" anchor rather than just clearing the field.
- "New category" is offered as the last row of the category typeahead's result list (image 02), not a separate button elsewhere — category creation is reachable from the same keystroke flow as category selection.
- The trend-chart callout bubble pins the budget ceiling value directly onto the chart at the y-height of the budget line (e.g., "$450.00" in 07, "$4,120" in 08) rather than only stating it in the text summary — the number is repeated in two places (summary text and chart) so the ceiling is visible while scanning the bars.
- The dashed-vs-solid bar-chart line style (image 08) to distinguish a pre-budget-tracking period from the actively-tracked period is a lightweight way to show data lineage/history depth without any accompanying caption.
- "Similar Transactions" (image 03) reuses the exact list-row visual grammar from the main transactions list (checkbox, merchant, category pill, amount) inside a detail panel — one component, two contexts — and groups them by month with a bold monthly total header.
- The "Regular Categories" tabular breakdown (image 08) pairs each SPENT/BUDGET/LEFT row with a small colored dot whose color appears driven by a finer-grained threshold than a flat over/under check (a small positive remainder still shows amber, not green, for "CAR $28.94 left") — suggesting a proportional-closeness rule rather than a binary sign check (unconfirmed, see Open questions).
