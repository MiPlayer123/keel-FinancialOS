## Business rules implied
- Register rows carry an independent cleared/uncleared status per transaction distinct from category assignment, and this status is filterable via structured query tokens ("Is: Uncleared", "Is: Cleared", "Is: Reconciled", "Is: Unreconciled", "Is: Cleared or Reconciled") — evidenced in `community-01`.
- A transaction can be simultaneously "Approved"/"Unapproved" independent of cleared status, and can lack a category ("Needs Category") — evidenced in `community-01`'s filter-token list, implying approval and categorization are separate required steps before a transaction is considered fully processed.
- Account balance is split into three explicit values that must reconcile: Cleared Balance + Uncleared Balance = Working Balance (shown as "-$360.00 + $150.00 = -$210.00" in the dimmed background of `community-01`) — a running-balance invariant surfaced directly in the UI.
- A budget category's "Available" figure can be reduced by scheduled future outflows before they clear — evidenced by the inspector's "1 Upcoming Transaction -$50.00" reducing "$100.00" Available Balance to "Available After Upcoming $50.00" in `community-03`, implying upcoming/scheduled transactions are netted against available funds ahead of time without altering the ledger.
- A budget category can be marked "Funded" as a discrete state distinct from showing a raw Activity number — evidenced by Rent/Electric rows in `community-03` — implying a rule where once a category's target is met for the period, the UI substitutes a status badge for the raw activity figure.
- Parent category-group rows aggregate child rows' Assigned/Activity/Available values (e.g., "Salaries & Wages - Mandy" group total ties to its children's negative/positive splits) — evidenced in `community-02`, implying strict roll-up arithmetic between group and child categories.
- Reports scope by three independent filters simultaneously — category set, date range, and account set — evidenced identically across `community-04`, `05`, `06`, implying all report types share one filtering/scoping model.
- Income v Expense treats "Savings" as an Expense-side category capable of a positive value ($300.00 while sibling expense rows are negative) — evidenced in `community-04` — implying the expense/income sign convention is about cashflow direction, not category type per se (a savings contribution can reverse/refund, shown as positive within the Expense group).
- Net worth reporting supports negative net worth values on the same chart/table as positive ones (axis crosses zero, table shows "-$7,583.66" for Jun 2021) — evidenced in `community-06`.
- The Loan Payoff Simulator recomputes both a "Payoff Date" and cumulative "Interest Remaining"/"Interest Savings" purely from Monthly Payment + one-time extra inputs, without touching the actual loan ledger until the user explicitly clicks "Copy and go to my budget" — evidenced by the simulator being a preview-first modal with a separate commit-style link, and a "Reset all changes" affordance that implies the edits are held in a scratch/staging state until copied — evidenced in `community-07`/`community-08`.

## Standout details
- Query-builder-as-autocomplete search: typing "is" in the register search surfaces structured filter tokens with paired status icons (hollow "c" vs filled green "c" vs padlock) rather than requiring a separate filter panel — a lightweight power-user affordance (`community-01`).
- The same banner slot (top-center of Budget) changes both color and copy based on state — green "Ready to Assign $X" when funds remain unassigned, tan/khaki "All Money Assigned $0.00" with a checkmark when fully assigned — status is co-located with the money it describes and shares one visual container, avoiding a separate status badge (`community-02` vs `community-03`).
- Inline per-cell undo affordance: a small clock/history icon sits directly next to the "Subscription" category's Assigned value in the budget table, letting a user undo just that one edit rather than a global undo (`community-03`).
- Category rows use small representative emoji/icon glyphs (money bag for Taxes, house for Rent, light bulb for Electric) purely for at-a-glance recognition scanning a long category list (`community-03`).
- Loan simulator's "Copy and go to my budget" link only appears once a field's value has actually changed from its default — progressive disclosure that avoids cluttering the UI with an action that has nothing to commit yet (`community-08`).
- Loan simulator relabels the *same* stat tiles from "Interest Remaining / Time Remaining" (baseline) to "Interest Savings / Time Savings" (once a hypothetical change is entered) — the framing of a number changes with context rather than introducing new UI elements (`community-07` vs `community-08`).
- Every stat block across the Reports section uses a consistent three-line pattern: small-caps label above → large bold figure → short italic/muted caption below (e.g., "TOTAL SPENDING / $18,946.86 / For this time period") — a repeatable "explain this number" micro-pattern applied consistently across Spending, Net Worth report sidebars (`community-05`, `community-06`).
- Net Worth report restates the same headline change twice in different forms: an absolute dollar change ("$19,042.25") immediately followed by a relative percentage ("251.1%") directly underneath, giving both magnitude and proportion at a glance (`community-06`).
