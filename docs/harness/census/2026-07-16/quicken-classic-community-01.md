## Information architecture
- Windows Quicken (images 2, 3, 7, 8) uses a persistent top blue nav bar with top-level sections: HOME, SPENDING, BILLS (& INCOME), PLANNING, INVESTING, PROPERTY & DEBT/RENTAL PROPERTY, ADD-ON SERVICES, MOBILE & ALERTS, TIPS & TUTORIALS (image 2); a business-edition variant (images 7, 8) instead shows HOME, SPENDING, BILLS & INCOME, PLANNING, INVESTING, PROPERTY & DEBT, BUSINESS, RENTAL, MOBILE & WEB — i.e. the nav set changes by product edition (personal vs. "Home, Business & Rental Property").
- A left-hand "ACCOUNTS" sidebar is persistent across all Windows and Mac screens (images 2, 4, 7, 8), grouped by type: Banking, Savings, Credit Card, Investing, Property & Debt (with Property and Debt sub-groups), Savings Goals, Separate — each group shows a rolled-up subtotal, and is expandable/collapsible (disclosure triangles in image 4/7/8's "Property & Debt" and "Investing" groups).
- Net worth is always one scroll/glance away: pinned at the bottom of the accounts sidebar as "Net Worth" plus a "Credit Score" readout directly beneath it (images 4, 7, 8) — net worth and credit score live with account navigation, not inside any content tab.
- Within a top-level section, secondary tabs appear directly under the nav bar: "Business" has "Profit/Loss", "Cash Flow", "Account Overview" (image 7); "Home" has "Main View" plus an "Add View" button implying multiple configurable dashboard views (image 8); a Mac Brokerage account has "Portfolio" and "Transactions" tabs (image 4).

## Flow steps
Reconciliation (inferred sequence from image 3 alone; no prior/next screen captured):
1. User opens "Reconcile: PREFERRED CHECKING XX0000" → sees two panes pre-populated with uncleared Payments/Checks and Deposits since last reconciliation, each row un/checked in "Clr".
2. User toggles "Clr" per matching statement line, or clicks "Mark All" → running per-pane count and subtotal update ("287 checks, debits -16,327.13", "36 deposits, credits 16,429.67").
3. User compares the boxed summary: Cleared Balance vs. Statement Ending Balance; a "Difference: 0.00" confirms match (success state) — a nonzero difference is presumably the not-yet-reconciled state, but that state is not captured in evidence.
4. User can "Edit"/"Delete"/"New" a transaction inline from within the dialog before finishing, or "Cancel" out, or "Finish Later" to pause, or click "Done" to complete (exact post-"Done" screen not captured).
No other multi-screen flow (e.g. onboarding, account linking) is present in this unit's images — omit further flow detail.

## Business rules implied
- Reconciliation match rule is stated verbatim in the dialog itself: pending transactions are matched by transaction Date within the statement period, while cleared transactions are matched by Posting Date within the statement period (image 3, bottom help text) — implies two different date fields drive inclusion depending on transaction status.
- Reconciliation success is defined as Cleared Balance == Statement Ending Balance, surfaced as a "Difference" of exactly 0.00 (image 3) — the UI computes and displays the delta rather than requiring the user to compute it.
- Debits and credits are reconciled as separate running subtotals ("checks, debits" vs. "deposits, credits"), each with its own transaction count, before being reduced to a single balance (image 3).
- Cash is treated as a distinct, non-security line within a portfolio's holdings table — it has a Market Value but no Price/Shares/Cost Basis/Gain-Loss columns populated (image 4), implying cash is not modeled as a "security" for cost-basis/gain-loss purposes.
- Cost basis can be zero/unknown for a security while Market Value is nonzero, and Gain/Loss is then computed as simply Market Value − 0 (image 4: AT&T Inc, Intuit Inc both show $0.00 cost basis against full market value as gain) — implies gain/loss calculation does not block on missing cost-basis data, it defaults it to zero rather than showing "N/A".
- Liability/debt account balances (credit card, line of credit, home loan, auto loan) are always shown as negative numbers in red across every sidebar instance (images 2, 4, 7, 8) — a consistent sign+color convention for liabilities vs. assets.
- Bill/income reminders carry a status taxonomy of at least "Overdue" (red, past due), "Auto" (clock icon, presumably auto-pay scheduled), and "Due" (clock icon, manually due) — evidenced by the three distinct badge/label pairs in image 8's reminders list.
- Spending dashboard scopes its headline total explicitly to "All Categories" and "12 Selected Accounts" (image 8) — implies spending totals are always computed against an explicit, visible account/category scope rather than an implicit "everything."

## Standout details
- Reconciliation dialog states its own matching rule as literal on-screen copy rather than leaving it to documentation — directly supports "reproducible numbers" style transparency.
- Every dashboard card in the Mac investing view repeats its own scope/total ("Total value $110,000") even when that figure is identical across sibling cards — redundant but leaves no ambiguity about what a given chart is a percentage of.
- Colored pill/chip treatment for percent and dollar deltas (green background, not just green text) is used consistently across Holdings, Top Movers, and Allocation cards (image 5) — a distinct, reusable "badge" idiom for calling out a change value versus a static one.
- Inline "?" help icons directly beside computed sub-metrics ("Last month's Loss", "Actual Profit this month", "Change from last month" in image 7) suggest per-number tooltips explaining provenance/formula — a pattern for building trust in a derived figure without leaving the card.
- The reconcile dialog visually boxes the three decisive numbers (Cleared Balance / Statement Ending Balance / Difference) apart from the transaction lists so the "did this work" answer is legible without scanning any row (image 3).
- Fractional share quantities are shown to 2–3 decimals (e.g., 0.15, 351.366) and price precision varies per security (22.17 vs 36.7188) rather than being forced to a fixed decimal count (image 6) — implies formatting adapts to the security's natural precision.
- The cents-with-a-gap-instead-of-a-decimal-point number rendering in the classic register (image 1: "59 76", "41,585 12") is a distinctive, unusual micro-typography choice worth noting even though its cause (font kerning vs. deliberate design) is unclear.
- Net Worth and Credit Score are pinned together at the very bottom of the persistent accounts sidebar in every multi-panel screen (images 4, 7, 8) — always-visible, chrome-level placement for the two "how am I doing overall" numbers.
