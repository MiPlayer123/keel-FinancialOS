## Information architecture
- Every screen (except the Dashboard) uses a persistent **three-pane layout**: (1) leftmost icon-rail/nav column with a Search field and a flat list of top-level destinations, followed by a "MY ACCOUNTS" grouped account list; (2) a middle **list/summary pane** for the current section; (3) a right **detail pane** for whichever item is selected in the middle pane.
- Left nav items observed, in order, on the Cash flow / Accounts / Recurrings / Categories / Investments screens: **Dashboard, Transactions (badge "11"), Cash flow, Accounts, Investments, Categories, Recurrings**. On the Dashboard screenshot the same rail instead reads **Dashboard, Transactions (badge "11"), Financial Goals, Cash flow, Accounts, Investments, Categories, Recurrings** — i.e. a "Financial Goals" entry appears between Transactions and Cash flow that is absent from the other six screenshots' rails. This is inconsistent across the marketing set (open question below).
- Below the primary nav, a persistent "MY ACCOUNTS" section groups accounts by collapsible type headers with a ▼ disclosure triangle: **Credit cards**, **Depository**, **Investment**. Each account row shows icon, name, last-4 mask (on Accounts/Investments screens) and current balance. This same account list (with only the balances differing slightly between screenshots, e.g. Chase Credit Card shows $7,478 in most screens but $6,620 on the Dashboard screenshot) appears unchanged across every screen, confirming it is a global, always-visible rail rather than page content.
- The account list is one click away from every section (it is literally always on-screen); tapping an account apparently opens its detail in the right-hand pane (shown already-selected for Chase Credit Card / Wealthfront in the Accounts/Investments screens).
- Detail panes follow one consistent internal structure regardless of entity type (account, recurring merchant, budget category, brokerage holding): header + identity row → trend/allocation chart with time-range tabs → a "Key metrics" collapsible table with a (?) info icon and 3 year-columns → a dated, grouped transaction list below.
- The AI-categorization screen (ipad-07) shows a two-pane (list + detail) sub-view of what is presumably the "Transactions" section, with the transaction detail one click from the transaction list (row for "Uber"/$26.60 is already highlighted).

## States
- **Empty state**: Categories detail pane, "November 2024 — No transactions yet this month" (exact quoted copy) shown in place of a transaction list for the current, not-yet-populated month.
- **Off/default toggle state**: "Show excluded spend" toggle rendered in its off position on the Cash flow screen.
- **To-review / pending state**: transaction detail header shows "• To review" as inline status text next to the date (not a separate banner), and the corresponding list row is implied to be part of a review queue (nav badge "11" on "Transactions").
- **Paid vs. unpaid state (implicit)**: Recurrings list — a ✓ checkmark on past/current-cycle rows (Nov 1–5) vs. no checkmark on today's-and-future rows (today's Lemonade Insurance, and Nov 15/21/28), a purely iconographic state distinction with no text label.
- **Over-budget warning state**: Dashboard "Monthly spending" card, callout copy "$88 over" attached directly to the chart at the crossover point; Categories detail chart uses red-colored bars for months that went over budget (no exact copy attached to those bars beyond the "$250.00" callout).
- **Capped/undefined percentage state**: "999%" badges shown wherever the year-ago comparison baseline is $0.00, apparently substituting for a mathematically undefined/infinite percent change.
- No loading or error states are visible in any of the seven images.

## Business rules implied
- A transaction can carry a "To review" status distinct from its confirmed state, and categorization can be AI-suggested (sparkle icon on the Category field) pending human confirmation via a "✓ Review" action — evidenced in `ipad-07`.
- Percentage-of-budget/utilization and favorability are visually distinguished by color independent of arrow direction: Assets ↗7.07% is green, Debt ↗0.83% is red, on the same card — evidenced in `ipad-06`.
- Recurring charges are tracked with an explicit rule set (name match, amount range, day-of-month, cadence) rather than a single fixed expected amount — the Spotify rule chips read "Named Spotify / from $6 to $15 / on any day of the month / every month" — evidenced in `ipad-03`.
- Budget status is computed and displayed per month, not just for the current period: the Groceries category detail chart color-codes individual past months (green/orange/red) against the $250 target — evidenced in `ipad-04`.
- Category budgets are hierarchical (parent categories such as "Home" or "Car & Transportation" roll up child categories such as Rent/Utilities or Car/Transportation, with the parent showing an aggregate spent/budget bar and a count badge of children) — evidenced in `ipad-04`.
- Accounts are grouped by a fixed taxonomy of types (Credit cards, Depository, Investment) with type-level subtotals — evidenced in `ipad-01` and `ipad-02`.
- Credit-card accounts display a balance-to-limit ratio ("$7,477.97 / $15,000.00") in addition to the raw balance, distinct from depository/investment accounts which show only a balance — evidenced in `ipad-02`.
- Investment performance is benchmarked against a specific selectable ticker (AAPL), not a fixed index, with the benchmark's own return percentage shown alongside the portfolio's — evidenced in `ipad-05`.
- Recurring items can be scoped to "This month" vs. "In the future" (i.e., annual/irregular-cadence items are bucketed separately from monthly current-cycle items) — evidenced in `ipad-03`.
- Comparisons against a zero-value prior period are handled by a capped "999%" display rather than an error or infinity symbol — evidenced across `ipad-01`, `ipad-02`, `ipad-06`.

## Standout details
- A small **sparkle icon** is reused as the app's consistent visual marker for "AI touched this": once on the transaction Category field (AI-suggested categorization) and once as the icon inside the "✨ Rebalance" budget action button — a single iconographic language for AI involvement across two different features.
- The Recurrings detail pane's timeline (`ipad-03`) uses a **solid dot line for realized months and a dashed line for projected future months** on the same chart — encodes certainty/confidence visually rather than via a legend or text.
- Detail panes across four unrelated entity types (bank account, recurring merchant, budget category, brokerage holding) all share the exact same content skeleton — chart w/ time tabs → allocation or rule chips → "Key metrics" table (2022/2023/2024 columns) w/ "(?)" tooltip → grouped dated transaction list — a strong reusable "entity detail" template rather than bespoke layouts per feature.
- The Dashboard's "$88 over" callout (`ipad-06`) is anchored directly to the chart pixel where the actual-spend line crosses the projected-pace line, rather than being a static number in a card header — the warning appears exactly where the money problem is, not just adjacent to a总-total figure.
- The "paid" state of a recurring bill (`ipad-03`) is communicated purely by a trailing checkmark glyph with no accompanying text — very low-chrome status encoding.
- Percent-change badges consistently place a small leading colored dot (gold/green/red) even on rows that also show a delta figure — providing a scannable color cue before the reader parses the number itself.
- The transaction detail screen's "Regular transaction" header (`ipad-07`) implies the same panel template is reused for at least one other transaction "kind" (transfer or split are the visible alternate actions in the toolbar: "Split"), i.e. transaction type is a first-class, named concept in the UI chrome itself.
